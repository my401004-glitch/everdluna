# 🌉 Reels 비주얼-데이터 통합 매핑 청사진 (Integration Blueprint - V1.0)

**[문서 목적]**
이 문서는 '스토리라인(Why)' $\rightarrow$ '기술적 데이터 변화(What)' $\rightarrow$ '시각적 구현 지침(How)'로 이어지는 **통합 로직 흐름도**이다. 모든 에이전트가 이 매핑을 따라 작업해야 한다.

---

## 1. 핵심 구조: Pain $\rightarrow$ Gain 스토리라인 기반
| 스테이지 | 현빈 (Narrative/Story) 역할 | 코다리 (Data/API Contract) 역할 | Designer (Visual Spec) 역할 | 통합 지침 및 액션 아이템 |
| :--- | :--- | :--- | :--- | :--- |
| **A. [Pain] Hook & 문제 인식** (0~3초) | **메시지:** "혹시 이런 부분이 고민이신가요?" 불안감을 자극하는 핵심 질문 제시. <br> *(예: '발성 시 호흡 지지력이 약합니다.')* | **데이터 변화:** `user_id` 기반 진단 데이터 호출. 낮은 점수(Pain Point)를 API로 전송받음. <br> *(`diagnosis_score`: 65/100)* | **시각 구현:** 부정적 감정 자극. 색상: #FF9800 (경고). 애니메이션: 불안정한 떨림, 낮은 채도, 흐릿한 트랜지션. | **[Action]** 진단 리포트의 'Pain Point' 섹션을 3초 분량의 영상으로 재현한다. <br> *필수 변수:* `score_low` (낮은 점수), `issue_keyword` (문제 키워드) |
| **B. [Problem] 근거 제시 및 충격** (4~8초) | **메시지:** "객관적 데이터로 보면, 이 부분이 가장 취약합니다." 수치와 데이터를 활용하여 문제의 심각성 증명. <br> *(예: '호흡 효율 점수는 평균 대비 30% 낮습니다.')* | **데이터 변화:** `issue_keyword`가 높은 가중치를 가지도록 API 로직을 재설정. 객관적 데이터 시각화 필요. <br> *(`data_deviation`: -30%)* | **시각 구현:** 그래프/차트 애니메이션 활용. 색상: #E57373 (위험). 애니메이션: 급격한 하강 곡선, 텍스트 오버레이로 수치 강조. | **[Action]** '데이터 편차'를 시계열 차트로 보여주고, 이 데이터가 곧 문제임을 명확히 인지시킨다. <br> *필수 변수:* `data_deviation` (변동률), `graph_type` (꺾은선 그래프) |
| **C. [Gain] 해결책 제시 및 전환** (9~15초) | **메시지:** "하지만, 이 방법으로 개선할 수 있습니다." 명확하고 구체적인 학습 로드맵/모듈을 제시하며 희망 부여. <br> *(예: 'XX 모듈을 통해 호흡 근육 강화 훈련이 가능합니다.')* | **데이터 변화:** 성공 사례 데이터 또는 목표 점수(`target_score`)를 API로 전송받아 대비 효과를 보여줌. <br> *(`diagnosis_type`: "Improvement", `target_score`: 95/100)* | **시각 구현:** 명료하고 밝은 색상 사용. 색상: #4CAF50 (성공). 애니메이션: 상승 곡선, 선명한 초점 이동, CTA 버튼 강조. | **[Action]** '개선 전'과 '개선 후 목표치'를 대비하는 시각적 비교를 통해 구매 동기를 최대화한다. <br> *필수 변수:* `target_score` (목표 점수), `CTA_trigger` (구매 유도 타이밍) |
