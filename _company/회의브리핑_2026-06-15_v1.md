# 🚀 [통합 회의 브리핑] 데이터 측정 시스템 통합 및 시각화 로직 논의 (Developer & Designer)

**목표:** 개별 기술 지표(Tech KPI)와 비즈니스 성과 지표(Business ROI/KPI)를 하나의 '성장 서사'로 통합하여, 사용자에게 보여줄 최종 리포트 구조 및 API 계약을 확정합니다.

---

### 💡 논의 배경 (지난 결정 사항 요약)
*   **핵심 컨셉:** 학생의 학습 과정 자체를 **‘좌절에서 승리로의 변곡점(Growth Story)’**이라는 서사로 포지셔닝하는 것이 최우선 목표입니다 [근거: Self-RAG].
*   **타겟 변화:** 초기 타겟은 실용음악 입시생 $\rightarrow$ 학원 운영자(교육기관 대표)로 확정되었습니다. 따라서 리포트의 초점은 '학생 개인 점수'보다 **'운영자의 투자 대비 효과(ROI)'와 '리스크 최소화 예측 지표'**에 맞춰져야 합니다 [근거: 영숙 검증된 지식].

### ⚙️ Part A. 기술적 요구사항 (코다리님 담당)
*   **핵심 로직:** 모든 분산된 진단 결과(음파 분석, 감정 데이터 등)를 취합하여 하나의 통합 보고서(`DiagnosisReportService`)를 생성하는 백엔드 서비스 레이어가 필요합니다 [근거: 코다리 산출물].
*   **API 계약 (필수 정의):** 최종 API 엔드포인트(`/api/v1/report/student_summary`)와 이 응답이 반드시 포함해야 할 핵심 데이터 필드가 확정되어야 합니다.
    *   *요구 사항:* 기술적 지표(PDI 변화량, Consistency Score 등)와 비즈니스 KPI를 매칭시키는 계산 로직의 인터페이스 정의가 필요합니다.

### 🎨 Part B. 시각화 요구사항 (디자이너님 담당)
*   **핵심 프레임워크:** 리포트는 **'Pain $\rightarrow$ Gain $\rightarrow$ Path'** 흐름을 따라야 합니다. 이 서사 구조가 디자인 전체를 지배해야 합니다 [근거: Designer 산출물].
*   **시각적 강조점:** 단순히 높은 점수를 보여주는 것이 아니라, '지금 얼마나 위험한지(Pain Point)'와 '이것을 해결하면 얼마나 큰 가치가 생기는지(Gain Roadmap)'를 **색상과 차트**로 충격적으로 대비시켜야 합니다.
    *   *요구 사항:* 기술적 지표가 어떻게 이 서사 구조(예: Pain/Gain 게이지)에 매핑될 수 있는지 시각적인 가이드라인을 확정해야 합니다.

### 🗓️ ✨ 논의 목표 (다음 단계 액션 아이템)
1.  **통합 필드 정의:** 기술적으로 필요한 모든 지표(A)와 디자인이 요구하는 모든 서사 요소(B)를 통합하여, 최종 API 응답 JSON 스키마에 포함될 **'최종 핵심 데이터 셋 목록'**을 확정한다. (가장 중요!)
2.  **데이터 흐름 정의:** 이 데이터 셋이 어떤 순서와 방식으로 사용자에게 보여질지 스토리보드(Designer)와 서비스 로직(Developer) 간의 인터페이스를 명확히 한다.
