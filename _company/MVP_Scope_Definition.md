# 🚀 MVP 최종 범위 정의: 'AI 기반 리스크 예측 진단 시스템'
**작성자:** 현빈 (Head of Business)
**목표:** 학원 운영자가 가장 절실하게 느끼는 Pain Point(학생의 잠재적 탈락 및 비효율 관리)를 해결하고, 단일 구독 모델을 통해 초기 매출을 확보하는 것.

## 1. 핵심 가치 제안 (Value Proposition)
*   **제목:** AI 기반 학생 리스크 예측 대시보드
*   **핵심 메시지:** 단순한 성적 보고서가 아닌, **'3개월 후 합격률이 가장 낮은 그룹의 명확한 원인과 해결책'**을 데이터로 제시하여 학원 운영자의 교육 계획 수립 및 입시 컨설팅 역량을 극대화합니다.
*   **경쟁 우위:** 시장에 존재하지 않던 '잠재적 실패 지표(Potential Failure Metric)'를 정량화합니다.

## 2. MVP 필수 기능 범위 (Scope)
| 카테고리 | 기능명 | 설명 및 핵심 KPI 연관성 | 중요도 |
| :--- | :--- | :--- | :--- |
| **[Data Input]** | 학생 학습 데이터 업로드 API | 코치/운영자가 학생들이 제출한 녹음, 설문지 데이터를 일괄 업로드할 수 있는 인터페이스. (Pitch Deviation Index, Breath Efficiency Score 등) | 필수(P0) |
| **[Core Engine]** | 리스크 예측 엔진 실행 로직 | 1. 학생 데이터 입력 $\rightarrow$ 2. Gap Score 산출 (L1 vs L2 비교). 3. **가장 취약한 모듈/영역을 Top-3으로 도출.** (예: 호흡 효율성 부족, 감정 일관성 미달) | 필수(P0) |
| **[Output/UI]** | 리스크 대시보드 (유료 영역) | - 학생별 '잠재적 위험 점수' 시각화. <br> - 운영자용 보고서: "이런 학생들에게 다음 주에 집중적으로 개입하세요."라는 CTA 제공. <br> - **[제한 기능]**: 이 리포트는 월 구독자에게만 접근 가능. | 필수(P0) |
| **[Monetization]** | 결제 및 권한 관리 시스템 연동 | 1. Stripe/PayPal API 연동 (월간 구독). 2. 구독 여부에 따라 '리스크 대시보드' 접근 제한 로직 구현. | 필수(P0) |

## 3. 기술적 검토 요청 사항 (Codari To Do List)
*   **요청:** 위 MVP 범위 중 P0에 해당하는 기능들이 **현존하는 API/기술 스택으로 어느 정도의 난이도와 시간(Estimate TTM)**을 가지고 구현 가능한지 상세하게 분석해 주십시오.
*   **결과물 기대:** 개발 우선순위 목록, 기술적 리스크 보고서, 초기 프로토타입 예상 일정 (Timeline).
