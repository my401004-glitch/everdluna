### ⚙️ [최종 제작 타임라인 & 실행 계획] (총 N일 기준)

#### **Phase 1: 프리-프로덕션 (Blueprinting)**
*   **목표:** 영상의 모든 골격(스크립트, 비주얼 컨셉)을 확정하고 승인받는다.
*   **책임자:** Writer $\rightarrow$ Leo (검증/승인) $\rightarrow$ Designer
*   **Gate Checkpoint 1: 최종 스크립트 및 후킹 확정.**
    *   Writer가 [세부 스크립트]를 완성하고, Hook(0-30초 분량)을 **숫자 기반 통계 자료로 무장**시킨다. (근거: 레오 개인 메모리)
    *   Leo는 스크립트의 논리가 'ROI/리스크 최소화' 관점에 충실한지 검토하고, 제목과 설명란에 들어갈 CTA(Call To Action) 문구를 최종 확정한다.

#### **Phase 2: 비주얼 컨셉 디자인 (Asset Creation)**
*   **목표:** 영상의 시각적 충격도를 극대화할 마스터 템플릿 및 에셋을 제작한다.
*   **책임자:** Designer $\rightarrow$ Leo (피드백)
*   **Gate Checkpoint 2: 마스터 썸네일 & 인포그래픽 승인.**
    *   Designer는 스크립트의 **가장 충격적인 통계 지표(예: 72%)를 전면에 배치**하는 Master Thumbnail 시안을 제작한다. ('Fear & Proof' 메시지 극대화)
    *   영상 내에서 사용될 모든 인포그래픽, 그래프, 위험 경고(빨간색/노란색)의 디자인 시스템 적용 범위를 확정하고 일관성을 검증받는다.

#### **Phase 3: 프로덕션 (Recording & Editing)**
*   **목표:** 스크립트와 비주얼을 결합하여 초안 영상을 완성한다.
*   **책임자:** Writer (Voice/나레이션) $\rightarrow$ Editor (최종 편집)
*   **Gate Checkpoint 3: 러프컷(Rough Cut) 검토.**
    *   에디터는 스크립트와 녹음된 보이스를 결합하여 초안을 완성하고, **시청자가 지루함을 느낄 만한 구간(Pacing Drop)**이 있는지 자체적으로 체크한다.
    *   Leo는 이 단계에서 컷 전환 속도, BGM의 긴장감 변화 등 '시청 지속 시간'에 영향을 주는 디테일을 중점적으로 피드백하여 재수정을 지시한다.

#### **Phase 4: 포스트-프로덕션 & 최적화 (Optimization)**
*   **목표:** 업로드 직전에 마케팅 효과를 극대화하는 메타데이터와 홍보 요소를 장착한다.
*   **책임자:** Leo $\rightarrow$ Designer/Writer
*   **Gate Checkpoint 4: 최종 패키지 완성.**
    1.  **제목 (Title):** [경고] + 문제 제기형 질문 + 구체적 수치 조합 확정. (예: `[🚨경고] 이 학생, 3개월 뒤에 학원을 떠날 확률이 72%입니다. 원인이 궁금하신가요?`)
    2.  **설명란:** 스크립트 요약 $\rightarrow$ 핵심 가치(ROI/리스크) 재언급 $\rightarrow$ CTA (무료 컨설팅 링크)를 반드시 포함한다.
    3.  **태그 및 키워드:** #학원운영자, #교육데이터분석, #학생이탈방지 등 광범위한 검색 노출용과 틈새시장(Niche) 전문성 강조용을 조합하여 배치한다.

#### **Phase 5: 배포 및 분석 (Launch & Iterate)**
*   **목표:** 업로드 후 성과를 측정하고 다음 콘텐츠에 반영할 데이터를 확보한다.
*   **책임자:** Leo $\rightarrow$ 모든 에이전트
*   **액션 항목:**
    1.  영상 게시 30분 전: Instagram/Facebook 등 외부 채널을 통해 트래픽 유입을 위한 예고 및 A/B 테스트용 홍보 이미지를 선행 배포한다. (근거: [2026-07-03] Instagram 활동)
    2.  업로드 후 1시간: 댓글 패턴 분석(Comment Harvester)을 즉시 실행하여 초기 시청자의 반응 키워드를 수집하고, 다음 영상 기획에 반영할 '반론'이나 '궁금증'을 메모리화한다.

## 🖼️ III. 핵심 모듈 세부 가이드라인 (The Flow)
### Module A: Pain Point 제시 컴포넌트 (불안감 유발 구간)
1.  **시각화:** 게이지(Gauge) 또는 막대 그래프 형태로 현재의 부족함/리스크를 보여줍니다.
2.  **핵심 요소:** `Gap Score` 위젯을 중앙에 배치합니다. 이 점수가 낮을수록 **Accent Yellow**로 경고등 효과를 줍니다.
3.  **텍스트 구조:** "현재 당신은 X%의 확률적 리스크에 놓여있습니다." (Montserrat Bold, Accent Yellow) + 구체적인 근거 데이터 제시 (Noto Sans KR).

### Module B: Transition/Breakthrough 컴포넌트 (전환점)
1.  **시각화:** 'A $\rightarrow$ B'의 화살표나 꺾임 그래프를 사용하여 변화의 임계점을 강조합니다.
2.  **핵심 요소:** 화면 전체에 **Dark Blue** 배경을 깔고, 중앙에 밝게 빛나는 듯한 (Glowing) Yellow-to-Blue 그라디언트 효과를 적용하여 시청자의 기대감을 극대화합니다.
3.  **연출 지침:** 이 구간에서는 잠시 음악의 톤이 상승하며 긴장감이 해소되기 직전의 '숨고르기' 느낌을 주어야 합니다.

### Module C: Gain/Solution 제시 컴포넌트 (해결책 및 성과)
1.  **시각화:** 성공적인 데이터 변화(성장 곡선)를 역동적으로 보여줍니다. 과거의 Pain Point가 딛고 올라서 높은 Peak에 도달하는 형태여야 합니다.
2.  **핵심 요소:** AI 시스템이나 솔루션 자체를 **Dark Blue** 배경 위에서 구조적이고 전문적인 그래픽(네트워크 노드, 알고리즘 시각화)으로 표현합니다.
3.  **최종 CTA:** 가장 중요한 성공 수치(`+Y점 향상`)는 반드시 Accent Yellow로 강조하고, '지금 바로 적용' 버튼을 배치하여 즉시 행동을 유도해야 합니다. (이 모듈은 모든 영상의 마지막 15초에 필수적으로 사용되어야 합니다.)

#### 2. 마스터 썸네일 컴포넌트 레이아웃 정의 (The Grid)
마스터 썸네일은 세 개의 논리적 모듈(3-Module Structure)로 구성되어야 합니다. 이는 'Fear & Proof' 전략을 시각적으로 분해한 것입니다.

1.  **[A] Pain Module (위험성 제시):** 가장 상단 또는 좌측에 위치하며, Dark Blue 배경 위에 Accent Yellow 경고선을 사용합니다.
    *   **내용:** "당신이 놓치고 있는 치명적 오류"와 같은 질문형 헤드라인.
    *   **시각화:** 빨간색/노란색 계열의 위험 그래프나 'X' 표시 아이콘을 활용하여 즉각적인 불안감을 조성합니다.
2.  **[B] Core Value Module (문제 정의 및 솔루션):** 중앙에 위치하며, 가장 크고 주목도가 높습니다. Dark Blue와 Neutral Grey가 대비됩니다.
    *   **내용:** 'Gap Score' 또는 '진단 결과'를 숫자로 명확히 제시합니다. (예: 72점 $\rightarrow$ 95점)
    *   **시각화:** 화살표(`$\uparrow$`)와 함께 상승 그래프를 배치하여, 해결책의 잠재력을 직관적으로 보여줍니다.
3.  **[C] Call to Action Module (명확한 결과):** 가장 하단 또는 우측에 위치하며, 배경을 Dark Blue와 대비되는 밝은 색(혹은 Accent Yellow)으로 처리합니다.
    *   **내용:** "AI 진단 로드맵 확인하기" 같은 구체적인 행동 지침과 '무료' 등의 키워드를 강조합니다.
    *   **시각화:** 직사각형 CTA 버튼 형태를 취하고, 배경에 노란색 그라디언트를 적용하여 클릭 유도를 극대화합니다.

*   **애니메이션 원칙 확립:** 모든 요소는 '데이터 기반의 움직임'을 가지도록 설계하며, 시청자의 시선을 유도하는 속도(Pacing)와 트랜지션(Transition)에 집중합니다.

#### 2. 컴포넌트별 애니메이션 제작 (가상 실행 및 가이드 생성)
다음은 확정된 디자인 시스템을 활용하여 핵심 모듈 3가지에 대한 구체적인 애니메이션 구현 지침입니다.

**A. Pain Point 시퀀스: '위험 감지(Risk Detection)'**
*   **목표:** 시청자의 불안감(Pain)을 극대화하며, 데이터의 위험성을 경고합니다.
*   **애니메이션 방식:** 텍스트는 타이핑 효과를 사용하되, 수치 그래프가 급격하게 하강하는 모습을 **빨간색 (⚠️ Accent Yellow와 대비되는 강조 컬러)**으로 표현하고, 배경에 노이즈(Grain) 필터를 적용하여 긴장감을 고조시킵니다.
*   **구체적 가이드:** `[Gap Score]` 수치가 30% 미만일 경우, 해당 지표 주변 영역에 경고 사각지대(Warning Overlay)가 깜빡이며 시선을 붙잡습니다.

**B. Solution 제시 시퀀스: '개입과 발견 (Intervention & Discovery)'**
*   **목표:** AI 솔루션의 도입을 통해 전환점이 발생했음을 직관적으로 보여줍니다.
*   **애니메이션 방식:** 어두운 배경(Dark Blue)에서 밝은 빛줄기 또는 데이터 플로우가 터져 나오며, **'해결책의 등장'**을 극적으로 연출합니다.
*   **구체적 가이드:** AI 진단 과정이 마치 복잡한 시스템을 스캔하듯 시각화되고, 해결책 키워드가 황금색(Accent Yellow)으로 빛나며 화면 중앙에 고정됩니다.

**C. Gain Point 시퀀스: '성장과 성취 (Growth & Achievement)'**
*   **목표:** 긍정적인 결과(Gain/ROI)를 데이터와 함께 폭발적으로 보여줍니다.
*   **애니메이션 방식:** 그래프가 급격히 상승하며, 과거의 낮았던 수치 대비 현재의 높은 수치를 **'도약하는 움직임'**으로 표현합니다.
*   **구체적 가이드:** 최종 목표 점수(`Target Score`)는 가장 크고 굵은 Montserrat Bold 타이포그래피와 함께, 마치 트로피를 받듯이 중앙에서 확대되는 효과를 적용하여 성취감을 극대화합니다.

```typescript
// /src/controllers/diagnosisController.ts (가정)

import { Request, Response } from 'express';

/**
 * GET /api/v1/diagnosis_score
 * 진단 점수 데이터를 가져와 시각적 요소 연동에 필요한 안정성을 확보합니다.
 */
export const getDiagnosisScore = async (req: Request, res: Response): Promise<void> => {
    try {
        // 1. 데이터베이스에서 DiagnosisResult를 가져옴 (기존 로직)
        const results = await db.getDiagnosisResults(req.params.contextId);

        if (!results || !results.result_data) {
            return res.status(404).json({ message: "진단 결과가 없습니다." });
        }

        // 2. 데이터 구조 검증 및 안정성 강화 (핵심 수정 부분)
        const diagnosisScore = results.result_data;
        
        // KPI 값에 대한 기본값(Default Value)과 유효성 플래그 추가
        const kpis = {
            Growth: { value: parseFloat(diagnosisScore?.kpi?.growth || '0'), isValid: true },
            Engagement: { value: parseFloat(diagnosisScore?.kpi?.engagement || '0'), isValid: true },
            Monetization: { value: parseFloat(diagnosisScore?.kpi?.monetization || '0'), isValid: true }
        };

        const responsePayload = {
            contextId: results.context_id,
            scoreLevel: diagnosisScore?.level || "Unknown",
            kpis: kpis, // 안정화된 KPI 객체 반환
            // 여기에 다른 시각적 요소에 필요한 메타 데이터 추가 가능
            metadata: {
                timestamp: new Date().toISOString(),
                source: 'API_V1'
            }
        };

        res.status(200).json(responsePayload);

    } catch (error) {
        console.error("데이터 진단 점수 API 호출 중 심각한 오류 발생:", error);
        // 🚨 중요: 에러 코드를 반환하되, 프론트엔드에서 처리할 수 있는 구조화된 에러 객체를 제공합니다.
        res.status(500).json({ 
            message: "시스템 데이터 서비스 이용 불가", 
            errorDetails: { code: 'SVC_UNAVAILABLE', details: (error as Error).message } 
        });
    }
};
```

| **Latency Threshold (LT)** | 진단 점수 API 호출 응답 시간이 최대 허용치(예: 500ms)를 넘지 않는 비율. | $\ge 99\%$ | 시각적 요소와 데이터가 동기화될 때 사용자 경험을 깨뜨리지 않도록 성능 확보. [근거: High Impact UX 원칙] |
| **Access Control Compliance (ACC)** | 요청된 `diagnosis_type`에 대한 RBAC 검증이 빠짐없이 수행되는 비율. | $100\%$ | 유료/무료 기능 분리(Monetization)의 핵심이자, 법적 안정성 확보. [근거: sessions/2026-05-18T13-43/developer.md] |

### 3. 백엔드 로직 실행 타임라인 설계 (Implementation Roadmap)

KPI를 달성하기 위한 백엔드 서비스는 순차적인 의존성을 가집니다. 따라서 다음 단계별(Phase) 개발을 통해 기술적 안정성을 확보하고, 영상 제작에 필요한 최종 API 스펙을 확정해야 합니다.

**Goal:** `GET /api/v1/diagnosis_score` 엔드포인트의 신뢰성 100% 달성.

#### Phase 1: Data Foundation & Core Logic (MVP 구축)
*   **목표 KPI:** DCR $\ge 99\%$ 확보.
*   **주요 작업:** `DiagnosisResult`와 `KPI_Metrics` 간의 트랜잭션 전후 검증 로직을 **강화(Enhance)**합니다.
*   **기술 스택/변경:** `diagnosisController.ts` 내부에 최종 데이터 삽입 직전에 3단계 (RBAC $\rightarrow$ Schema Validation $\rightarrow$ FK Check)를 통과시키는 **트랜잭션 게이트웨이** 로직을 추가해야 합니다.

#### Phase 2: Performance & Security Layer (안정성 확보)
*   **목표 KPI:** LT $\ge 99\%$ 및 ACC $100\%$ 달성.
*   **주요 작업:** API 호출 성능 최적화(Caching, Asynchronous 처리)와 RBAC 로직의 예외 케이스를 검증합니다.
*   **기술 스택/변경:**
    1.  API 게이트웨이 레벨에서 Rate Limiting과 기본적인 인증(AuthN)을 구현하여 안정적인 호출 환경을 만듭니다.
    2.  Redis 캐싱 레이어를 도입하여 반복되는 진단 점수 계산 요청에 대한 부하를 줄이고 LT 목표치를 달성합니다.

#### Phase 3: Production Readiness & Monitoring (최종 검증)
*   **목표 KPI:** 모든 KPI $100\%$ 달성 및 모니터링 시스템 구축.
*   **주요 작업:** 실제 트래픽 상황을 가정하여 부하 테스트(Load Testing)를 진행하고, 운영 환경에 필요한 로깅/모니터링 시스템을 통합합니다.
*   **기술 스택/변경:** Prometheus와 같은 메트릭 수집 도구를 도입하여 DCR, LT, ACC가 실시간으로 추적되도록 합니다.
