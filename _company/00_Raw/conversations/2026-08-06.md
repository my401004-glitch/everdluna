*   **Function:** 진단 점수와 사용자의 현재 학습 단계를 입력받아, 가장 효과적인 **다음 콘텐츠 주제 및 구조(Timeline)**를 추천합니다. (데이터 $\rightarrow$ 콘텐츠 매핑)
*   **Request Body 예시:**
    ```json
    {
      "diagnosis_id": "uuid-12345",
      "user_level": "beginner", 
      "preferred_focus": "voice_stability" // 사용자가 관심 가진 영역
    }
    ```
*   **Response Payload 핵심 (E2E 테스트 대상):**

### 🧪 2. E2E 테스트 스위트 설계 (System Stability Check)

API 엔드포인트만 정의해서는 안 됩니다. 이 데이터 흐름이 깨지면 비즈니스 로직 전체가 마비됩니다. 따라서, 최소한 다음 세 가지 시나리오에 대한 **End-to-End(E2E) 테스트 스위트**를 설계합니다. 저는 이를 `test_e2e_kpi_pipeline.py` 파일로 구현할 계획입니다.

#### Test Case 1: Happy Path (정상 흐름 검증)
*   **시나리오:** 정상적으로 데이터가 수집되고, 로직이 계산되며, 유효한 콘텐츠 구조가 반환되는 가장 이상적인 경우.
*   **테스트 목표:** `GET /diagnosis_score` $\rightarrow$ (결과 JSON 추출) $\rightarrow$ `POST /content-structure` $\rightarrow$ (유효한 Timeline 배열 반환).
*   **검증 포인트:** 모든 KPI 비율이 0~1 사이의 유효한 실수여야 함. 추천된 콘텐츠 주제가 실제 존재하는 주제 리스트에 포함되어야 함.

#### Test Case 2: Edge Case - Zero Input Data (시스템 안정성 검증)
*   **시나리오:** 사용자가 진단 테스트를 시작했으나, 녹음 파일 업로드 등의 과정에서 필수 데이터(예: 음역대 데이터)가 누락된 경우.
*   **테스트 목표:** 시스템 크래시 없이 정의된 기본값(Fallback Value)을 반환하고, 사용자에게 명확한 에러 메시지를 제공하는지 검증.
*   **검증 포인트:** API는 500 Internal Server Error 대신 **422 Unprocessable Entity** 코드를 반환하며, 응답 바디에 "필수 데이터 누락: [누락된 데이터 이름]"이 포함되어야 함. (가드 로직 테스트)

#### Test Case 3: Business Logic - RBAC Failure (권한 검증)
*   **시나리오:** 무료 사용자(Role='Free')가 유료 서비스 콘텐츠 구조 추천 요청을 시도하는 경우.
*   **테스트 목표:** 데이터 계산은 수행하되, 민감한/프리미엄 콘텐츠(`Monetization` 관련 심화 분석)의 상세 내용 접근 자체를 차단하고 대체 정보를 반환합니다.
*   **검증 포인트:** API는 403 Forbidden을 반환하거나, 혹은 `content_structure` 배열 내에 **"Premium Content: Requires Upgrade"**라는 플래그가 명시되어야 합니다.

## 📊 KPI 매핑 로직 최종 확정 및 검증 기준 정의

**목표:** 데이터의 신뢰성 확보 및 개발(코다리) 검증을 위한 명확한 연결 고리 정의.

기존 `Metric_Mapping_Plan_v1.md`에 정의된 항목들을 바탕으로, 각 KPI가 어떤 데이터 필드에서 파생되어야 하며, 그 관계를 코다리가 검증할 수 있는 논리적 규칙(Logic Rule)을 다음과 같이 최종 확정합니다.

### 1. 핵심 매핑 테이블 (최종 확정 버전)

| KPI (목표) | 핵심 측정 데이터 필드 | 계산 로직 (Logic Rule for Koda-ri) | 필수 검증 조건 |
| :--- | :--- | :--- | :--- |
| **성장 증명 (Growth)** | `pitch_deviation_index`, `breath_efficiency_score` | $Growth = (\text{Target\_L2} - \text{Current\_L1}) / \text{Gap\_Score}$ | $\text{Pitch\_Deviation Index} > 0$ 이고, $\text{Breath\_Efficiency Score}$가 $\text{Threshold}$ 이상이어야 함. |
| **참여도 (Engagement)** | `feedback_received`, `emotional_consistency_score` | $Engagement = (\text{Feedback\_Count} / \text{Total\_Modules}) \times 100$ | $\text{Feedback\_Received}$ 값이 0이 아니어야 하며, 평균 점수가 $\text{Baseline\_Score}$보다 높아야 함. |
| **수익화 잠재력 (Monetization)** | `completed_modules`, `LTV_Potential` | $Monetization = (\text{Completed\_Modules} / \text{Total\_Required}) \times \text{Price\_Tier}$ | $\text{Completed\_Modules}$가 목표 대비 $\ge 80\%$ 이상 달성되어야 하며, $\text{LTV\_Potential}$이 설정된 구독 가격에 도달해야 함. |

### 2. 코다리 검증을 위한 상세 로직 정의 (Validation Logic)

코다리는 다음의 로직을 기반으로 시스템의 출력값($Growth, Engagement, Monetization$)이 실제 데이터(`pitch_deviation_index`, `feedback_received` 등)로부터 **수학적으로 유도**되었는지 확인해야 합니다.

#### A. 성장(Growth) 검증 로직
1.  **입력 조건:** $PDI$ (Pitch Deviation Index), $BES$ (Breath Efficiency Score), $L_{current}$ (현재 레벨), $L_{target}$ (목표 레벨).
2.  **검증 단계:**
    *   **Step 1 (Gap Calculation):** $\text{Gap\_Score} = \text{Map}(L_{target}, L_{current})$ 로 계산된 목표치와의 격차를 확인한다.
    *   **Step 2 (Growth Factor):** $Growth = (\text{Target\_L2} - \text{Current\_L1}) / \text{Gap\_Score}$ 를 계산하여 실제 성장률을 산출한다.
    *   **Step 3 (Constraint Check):** 만약 $PDI < \text{Min\_Threshold}$ 또는 $BES < \text{Min\_Threshold}$ 이면, $Growth$ 값은 **'잠재적 성장(Potential Growth)'**으로 분류하고, 실제 성장은 '진행중'으로 표시한다.
3.  **결론:** 시스템이 제시한 $Growth$ 값이 $\text{Gap\_Score}$와 기술 지표($PDI, BES$)의 관계에 의해 논리적으로 도출되었는지 확인한다.

#### B. 참여도(Engagement) 검증 로직
1.  **입력 조건:** $\text{Feedback\_Received}$, $\text{Total\_Modules}$.
2.  **검증 단계:**
    *   **Step 1 (Completion Rate):** $\text{Completion Rate} = (\text{Feedback\_Count} / \text{Total\_Modules}) \times 100$ 를 계산한다.
    *   **Step 2 (Consistency Check):** $\text{Emotional Consistency Score}$가 평균 점수 대비 편차($\sigma$)를 분석하여, 사용자가 특정 감정 표현에서 일관성을 유지했는지 확인한다.
    *   **Step 3 (Engagement Scoring):** $Engagement = \text{Completion Rate} + (\text{Emotional Consistency Score} / 100)$ 로 계산한다.
3.  **결론:** $\text{Engagement}$ 점수가 사용자가 학습 과정에 얼마나 깊이 관여했는지(참여)를 반영하는지 확인한다.

#### C. 수익화 잠재력(Monetization) 검증 로직
1.  **입력 조건:** $\text{Completed\_Modules}$, $\text{Price\_Tier}$ (구독 레벨).
2.  **검증 단계:**
    *   **Step 1 (Progress Check):** $Completion Rate = (\text{Completed\_Modules} / \text{Total\_Required}) \times 100$ 를 계산한다.
    *   **Step 2 (Monetization Index):** $\text{Monetization Index} = \text{Completion Rate} \times \text{Price\_Tier}$ 로 잠재 수익을 산출한다.
    *   **Step 3 (LTV Validation):** $\text{Monetization Index}$가 최소 기준($\text{Minimum\_Conversion\_Rate}$)을 충족하는지 확인한다.
3.  **결론:** 데이터 기반으로 사용자가 유료 전환에 도달할 가능성을 객관적으로 평가했는지 검증한다.

/**

export interface DiagnosisRequestWithAuth {

## 💡 1. 대시보드 구조 및 데이터 흐름 설계 (Data Flow Architecture)

대시보드는 총 3단계의 시각적 경험을 제공하며, 각 단계는 상호작용합니다.

| 영역 | 목적 (사용자 감정) | 핵심 기능/데이터 활용 | 디자인 원칙 적용 |
| :--- | :--- | :--- | :--- |
| **A. 요약 및 진단 (The Hook)** | "내가 지금 어떤 문제에 직면했는가?" (Pain 인식) | 전체 점수(Composite Score), 가장 취약한 KPI 3가지 Top-N 제시. | **[🔴 Accent Yellow]** 위험/문제 지점 강조.
| **B. 상세 분석 및 비교 (The Why)** | "왜 이런 문제가 발생했는가? 무엇을 개선해야 하는가?" (원인 파악) | Gap Score와 Emotional Consistency Score의 추이 그래프(Timeline), 각 점수의 세부 구성요소 분해. | Dark Blue (`#0A2463`)를 통해 전문적인 분석 신뢰감 부여.
| **C. 해결책 제시 및 행동 유도 (The Solution)** | "나에게 무엇을 해야 하는가?" (Gain/Action) | 개선 우선순위(Priority), 구체적 학습 모듈 추천, 다음 스텝 CTA. | **[🟢 Green / Accent Yellow]** 명확한 목표와 기회 강조.

### Component B: KPI 추이 분석 (Trend Analysis Graph)
*   **위치**: 대시보드 중앙부, 가장 많은 공간을 차지하는 차트 영역.
*   **데이터 소스**: `diagnosis_score` API의 시간(Time Series Data).
*   **구조**: **Dual-Axis Line Chart**. X축은 '시간', Y축은 '점수'.

3.  **전환점 표시:** 가장 점수가 크게 상승하는 지점(Peak)에는 **[Gain]** 마크업과 함께 해당 성취의 원인 분석을 팝업으로 제공합니다.

2.  **콘텐츠 추천 (CTA):** 해당 약점 영역을 보완할 수 있는 구체적인 학습 모듈/강의(외부 콘텐츠) 목록을 카드 형태로 제시합니다. 이 카드는 **Accent Yellow (`#FFD700`) 배경과 Dark Blue 텍스트**로 강조되어 즉각적인 클릭을 유도해야 합니다.

/**
 * @fileoverview KPI_Gauge Component: 핵심 지표의 수치적 상태와 위험도를 게이지 형태로 표시합니다.
 * 이 컴포넌트는 PresentationValidatorService에서 확정된 '상태(State)' Props를 받아 시각 로직을 발동시킵니다.
 */

import React from 'react';

// --- 🎨 Design Tokens & Types ---
export type ScoreLevel = 'Danger' | 'Warning' | 'Normal' | 'Success';

interface KPI_GaugeProps {
  /** 지표의 이름 (예: Gap Score, Emotional Consistency) */
  kpiName: string;
  /** 현재 측정된 수치 값 (0~100) */
  scoreValue: number;
  /** 데이터가 속한 카테고리/지표 타입. UI에 추가 정보를 제공합니다. */
  metricType: 'Academic' | 'Emotional' | 'Financial';
  /** PresentationValidatorService에서 계산된 상태 레벨 (Danger, Warning 등) */
  visualLevel: ScoreLevel; 
}

// --- Component Implementation Start ---
const KPI_Gauge: React.FC<KPI_GaugeProps> = ({ kpiName, scoreValue, metricType, visualLevel }) => {
  
  // 1. Dynamic Color & Style Mapping (가장 중요한 디자인 로직)
  let levelColor: string; // 배경색/게이지 색상
  let labelText: string; // 사용자에게 보여줄 상태 설명

  switch (visualLevel) {
    case 'Danger':
      levelColor = '#D9534F'; // Red 계열 - 위험
      labelText = `위험! ${kpiName} 점수(${scoreValue})는 즉각적인 개선이 필요합니다.`;
      break;
    case 'Warning':
      levelColor = '#FFD700'; // Accent Yellow - 주의/기회
      labelText = `주의: ${kpiName} 점수(${scoreValue}). 잠재적 위험 구간에 있습니다.`;
      break;
    case 'Normal':
      levelColor = '#5BC0DE'; // Blue 계열 - 보통/평균
      labelText = `${kpiName} 점수가 평균 수준입니다. 꾸준한 관리가 필요합니다.`;
      break;
    case 'Success':
      levelColor = '#5CB85C'; // Green 계열 - 성공/최적화
      labelText = `훌륭해요! ${kpiName} 점수(${scoreValue})는 최적의 상태입니다.`;
      break;
    default:
      levelColor = '#CCCCCC';
  }

  // 2. UI Structure (Props 기반으로 재사용 가능한 구조)
  return (
    <div style={styles.container}>
      {/* Header */}
      <div style={styles.header}>
        <h3 style={styles.title}>{kpiName} ({metricType})</h3>
      </div>

      {/* Gauge Visual Area */}
      <div style={styles.gaugeContainer}>
          <div style={{ 
              ...styles.gaugeFill, 
              backgroundColor: levelColor, // 상태에 따른 색상 적용
              width: `${scoreValue}%` 
          }}></div>
          <span style={styles.scoreText}>{Math.round(scoreValue)}%</span>
      </div>

      {/* Status & Call to Action */}
      <div style={styles.statusBox}>
        <p style={styles.statusMessage}>{labelText}</p>
        <button 
            style={{...styles.ctaButton, backgroundColor: levelColor}} 
            onClick={() => console.log('CTA Clicked for', kpiName)}
        >
          {visualLevel === 'Danger' ? '진단받기 (Action Required)' : '더 알아보기'}
        </button>
      </div>
    </div>
  );
};

export default KPI_Gauge;
</create_file>
