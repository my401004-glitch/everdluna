# 🎬 영상 스크립트 핵심 프레임워크: [Pain $\rightarrow$ Process $\rightarrow$ Gain]

**💡 주제 가설:** 'Impossible Score'를 달성하기 위해 감성적 노력 대신 **객관적인 데이터 기반 시스템(AI)**을 사용하는 방법.

## 1. 후킹 문구 (Hook) 전략: Pain 극대화 및 충격 제시
**(목표: 시청자가 즉시 자신의 문제임을 인지하고 영상을 끝까지 보게 만든다.)**

### A. 강력한 질문형 후크 (Curiosity & Doubt 유도)
> **"당신이 지금 연습하는 발성법이 사실은 '노력'이 아니라 '불안정한 소리'를 내고 있다면?"**
> *[추가 멘트]* "선생님들이 말하는 '목을 열어라', '복식 호흡하라'는 조언만으로는 왜 당신의 음정 편차(Deviation)가 줄지 않는 걸까요? 그 답은 감성이 아니라, 당신이 놓치고 있는 **객관적인 데이터**에 있습니다."

### B. 통계/충격형 후크 (Shock & Urgency 유도)
> **"실용음악 입시생 90%가 모르는 '발성 주파수'의 비밀: 당신의 소리는 정말 합격할 준비가 되어 있습니까?"**
> *[추가 멘트]* "감정적인 노력은 잠시 멈추세요. 지금부터 우리는 AI를 이용해 당신의 목소리가 **합격에 필요한 객관적 기준치(Gap Score)**에서 얼마나 벗어나 있는지 측정하고, 정확히 보정하는 시스템을 만들 겁니다."

## 2. 논리 흐름 (Logical Flow): Process 제시 및 Gain 증명
**(목표: 문제 제기 후, AI 기반의 명확한 해결 과정과 그 결과(성장)를 제시하여 신뢰와 행동을 유도한다.)**

### 단계 1: Pain (문제 명확화) - **"감성의 함정"**
*   **핵심 메시지:** 기존의 코칭 방식(감성적 조언)이 왜 실패하는가?
*   **내용 구성:**
    *   "많은 선생님들은 '느낌'으로 가르칩니다. 하지만 음악은 감성만으로 완성되지 않습니다." (기존 방식 비판)
    *   "당신의 발성이 불안정한 이유는 **주파수 불균형** 때문입니다. 당신이 느끼는 불편함은 사실, 기술적 결함의 신호입니다." (Gap Score와 주파수의 관계 제시)
    *   *강화 포인트:* "노력만으로는 부족하다. 객관적인 수치가 필요하다."

### 단계 2: Process (해결 시스템 제시) - **"AI 기반 객관성 확보"**
*   **핵심 메시지:** Pain을 해결하기 위한 구체적이고 체계적인 시스템(AI 솔루션)을 소개한다.
*   **내용 구성:**
    *   **시스템 도입:** "우리는 감성이 아닌, **'Gap Score' 기반의 데이터 시퀀싱 시스템**을 도입합니다." (회사 정체성 반영)
    *   **AI의 역할:** AI가 어떻게 당신의 발성 주파수와 공명 영역을 측정하고, 그 편차(Gap)를 분석하는지 구체적인 프로세스를 제시한다. (예: A4 음역대에서 실제 공명 주파수를 측정 → 목표 지점과의 차이 계산)
    *   **단계별 설명:** '측정 $\rightarrow$ 진단 $\rightarrow$ 보정 $\rightarrow$ 최적화'의 4단계 과정을 시각적으로 보여준다.

### 단계 3: Gain (결과 증명) - **"좌절에서 승리로의 변곡점"**
*   **핵심 메시지:** 시스템을 통해 얻게 되는 실질적인 이득(객관성, 확신, 빠른 성장).
*   **내용 구성:**
    *   **데이터 기반 변화:** "이 시스템을 적용했을 때, 학생들은 **'막연한 노력' 대신 '측정 가능한 목표'**를 갖게 됩니다." (학부모/학생의 심리적 변화 강조)
    *   **결과 제시 (Proof):** 실제 데이터 변화 예시(Before/After 그래프), 혹은 성공 사례(사례 중심)를 통해 시스템의 강력함을 증명한다.
    *   **최종 CTA:** "더 이상 감에 의존하지 마세요. 당신의 잠재력을 해방할 **객관적인 성장 로드맵**을 지금 바로 확인하세요." (CTA 유도)

## 1. [New] POST /api/v1/event (Event Logging)
*   **설명:** 사용자가 특정 시각적 요소와 상호작용한 모든 이벤트를 비동기적으로 로깅합니다. 최종 점수 제출이 아닌, **'사용자 여정 추적(Journey Tracking)'** 목적입니다.
*   **요청 바디 (Request Body) 스키마 예시:**

```json
{
  "user_id": "UUID",             // 필수: 사용자 식별자
  "session_id": "UUID",           // 필수: 세션 식별자
  "timestamp": "ISO 8601 String", // 필수: 이벤트 발생 시간
  "event_type": "STRING",        // 필수: 이벤트의 종류 (예: 'hover', 'click', 'scroll', 'focus')
  "context_id": "UUID/STRING",   // 선택: 이 상호작용이 속한 컨텐츠 블록 ID (예: A-01)
  "asset_details": {              // 필수: 어떤 에셋과 관련되었는지 상세 정보
    "asset_id": "A-01_RiskIndicator", 
    "name": "위험도 시각화 인디케이터",
    "component_type": "SVG/Canvas" // 사용된 기술 타입
  },
  "payload": {                    // 선택: 이벤트에 특수한 데이터 (예: hover의 경우 X, Y 좌표)
    "x_coordinate": 120,
    "y_coordinate": 350,
    "duration_ms": 50 // 지속 시간 등 추가 측정값
  }
}
```

## 2. [Update] DiagnosisResult Schema (Data Model Extension)
*   **기존 테이블:** `Diagnosis_Results`
*   **추가 필드/처리 로직:**
    1.  **Event Aggregation Key (`event_key`)**: 진단 결과에 가장 큰 영향을 미친 상위 3개의 `asset_id`를 기록하는 배열을 추가합니다. (예: `["A-02_ComparisonGraph", "A-01_RiskIndicator", "B-03_ActionItem"]`)
    2.  **데이터 모델 변화:** 최종 결과(DiagnosisResult)가 단순히 점수만을 담는 것이 아니라, **'주요 상호작용 근거 (Key Interaction Evidence)'**를 포함하도록 변경합니다.

## 3. [New] Event Types Definition (Reference for Frontend)
*   **`hover_entry`**: 사용자가 특정 에셋 영역에 진입했을 때 발생. (`payload`: `asset_id`, `x/y`)
*   **`hover_exit`**: 사용자가 해당 에셋 영역을 벗어났을 때 발생. (`payload`: `asset_id`)
*   **`click`**: 버튼이나 상호작용 가능한 요소 클릭 시 발생. (`payload`: `element_xpath`, `target_data`)

### 🛠️ Step 2: 미세 상호작용 이벤트 데이터 모델(SQL) 설계

-- ----------------------------------------------
-- MicroInteractionLog: 미세 상호작용 이벤트 추적 테이블
-- Purpose: 사용자가 특정 애니메이션 에셋이나 UI 요소와 '어떻게' 상호작용한지 기록합니다. (KPI의 Engagement 측정 핵심)
-- FKs are critical for data integrity and linking back to the source event/session.
-- ----------------------------------------------

CREATE TABLE MicroInteractionLog (
    log_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_fk BIGINT NOT NULL, -- 사용자 ID (Users 테이블 참조)
    session_fk BIGINT NOT NULL, -- 해당 상호작용이 발생한 세션 ID (SessionDetails 테이블 참조)
    asset_id VARCHAR(50) NOT NULL, -- Designer가 정의한 애니메이션 에셋 고유 ID (예: A-01_PITCH_VISUALIZER)
    interaction_type ENUM('hover', 'click', 'scroll_depth', 'focus', 'dwell') NOT NULL, 
    interaction_timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP, -- 이벤트 발생 시간
    duration_ms INT, -- 상호작용 지속 시간 (밀리초). dwell(머무름) 측정에 사용.
    context_data JSON, -- 추가적인 맥락 데이터 (예: scroll percentage, button name 등)

    -- Constraints & Indexes for Performance
    FOREIGN KEY (user_fk) REFERENCES Users(user_id) ON DELETE CASCADE,
    FOREIGN KEY (session_fk) REFERENCES SessionDetails(session_id) ON DELETE CASCADE,
    INDEX idx_asset_interaction (asset_id, interaction_type, interaction_timestamp) 
);

-- [Note]: 이 테이블은 기존의 Diagnosis_Results에 기록되는 '결과'가 아닌, '행동 로그'를 저장합니다.
</create_file>
