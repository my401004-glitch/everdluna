## 2. 핵심 모션 그래픽 스펙 (Gap Score Visualization)

**[A. Gap Score 측정 순간 (Pain Point)]**
1. **진입:** 그래프가 좌측에서 오른쪽으로 빠르게 '스캔' 되며 데이터를 추출하는 애니메이션을 사용한다. (빠른 속도, 긴장감 고조).
2. **시각화:** 이상적인 주파수 밴드(Ideal Band)는 은은한 Dark Blue로 표시하고, 실제 측정된 주파수는 Muted Red 또는 Yellow 영역에 '점'으로 찍힌 후, 목표 범위에서 벗어난 거리만큼 *빨간색 간격*이 벌어져 보이도록 애니메이션화한다.
3. **텍스트 효과:** "Deviation:", "Gap Score:" 등의 텍스트는 튀어나오는(Pop-in) 모션과 함께 강조되어야 한다.

**[B. 해결책 제시 순간 (Gain Point)]**
1. **전환:** Muted Red로 표시되던 간격이 Yellow/Blue 계열의 부드러운 파동 애니메이션으로 채워지며 'Gap'가 닫히는(Closing Gap) 모션을 보여준다.

```python
import json
from typing import Dict, Any

# --- 🛠️ 가정한 시스템 상수 및 스키마 ---
EXPECTED_SCHEMA = {
    "user_id": str,
    "diagnosis_type": str,  # 예: 'Pitch', 'Frequency Stability'
    "context_id": str,      # 세션 고유 ID
    "timestamp": str,       # ISO Format
    "result_data": dict,    # 진단 결과 JSON 스키마 (핵심)
}

KPI_FIELDS = ["Growth", "Engagement", "Monetization"]


def validate_kpi(kpis: Dict[str, Any]) -> bool:
    """진단 결과 내의 KPI 필드들을 검증합니다. 값이 숫자인지 확인합니다."""
    for field in KPI_FIELDS:
        if field not in kpis or not isinstance(kpis[field], (int, float)):
            print(f"[ERROR] KPI '{field}'가 누락되었거나 유효한 숫자 타입이 아닙니다.")
            return False
    return True


def validate_diagnosis_data(raw_json: str) -> Dict[str, Any]:
    """API Mockup 데이터를 읽어와 스키마 및 비즈니스 로직에 따라 검증합니다."""
    print("\n--- 🚀 데이터 유효성 검증 시작 ---")
    try:
        data = json.loads(raw_json)
    except json.JSONDecodeError:
        raise ValueError("유효하지 않은 JSON 형식입니다.")

    # 1. 기본 스키마 체크 (핵심 필드 존재 여부)
    for field, expected_type in EXPECTED_SCHEMA.items():
        if field not in data or not isinstance(data[field], expected_type):
            raise TypeError(f"필수 필드 '{field}'가 누락되었거나 타입이 다릅니다. (기대: {expected_type.__name__})")

    # 2. KPI 검증 (비즈니스 로직 통합)
    kpis = data['result_data'].get('kpi', {})
    if not validate_kpi(kpis):
        raise ValueError("진단 결과 내의 핵심 KPI 데이터에 문제가 있습니다.")

    print("[✅ SUCCESS] 전체 스키마 및 KPI 유효성 검증 통과. 데이터를 이용해 시각화 준비 완료.")
    return data


def simulate_api_call(mockup_json: str):
    """가상의 API 호출을 시뮬레이션하고 결과를 출력합니다."""
    print("==============================================")
    print("🚀 [API 통합 검증] Mockup Data를 이용한 백엔드 로직 실행")
    print("==============================================")

    try:
        validated_data = validate_diagnosis_data(mockup_json)
        # 이 단계에서 성공적으로 파싱되고 스키마에 맞는 데이터가 나왔음을 확인했습니다.
        return validated_data
    except (ValueError, TypeError) as e:
        print(f"\n[❌ FAILED] 데이터 통합 오류 발생: {e}")
        print("==============================================")
        return None


if __name__ == "__main__":
    # Designer가 제시했다고 가정한 Mockup JSON 예시 (성공 케이스 시뮬레이션)
    MOCKUP_SUCCESS = json.dumps({
        "user_id": "user-1234",
        "diagnosis_type": "Pitch Consistency",
        "context_id": "session-abcde",
        "timestamp": "2026-06-25T10:00:00Z",
        "result_data": {
            "score": 78.5,
            "feedback": "전반적인 피치 안정성이 우수합니다.",
            "kpi": {
                "Growth": 3.2,      # 성장 지표 (높음)
                "Engagement": 4.1,  # 몰입도 (매우 높음)
                "Monetization": 1.5 # 유료 전환 가능성 (보통)
            }
        }
    })

    # 실패 케이스 시뮬레이션 (데이터 누락/오류 발생 가정)
    MOCKUP_FAILURE = json.dumps({
        "user_id": "user-9999",
        "diagnosis_type": "Pitch Consistency",
        "context_id": "session-fail",
        "timestamp": "2026-06-25T10:00:00Z",
        "result_data": {
            "score": 45.0,
            # 'kpi' 필드가 누락되어 오류를 발생시킴
        }
    })

    print("\n\n==================== [테스트 케이스 1: 성공] ====================")
    simulate_api_call(MOCKUP_SUCCESS)

    print("\n\n==================== [테스트 케이스 2: 실패] ====================")
    simulate_api_call(MOCKUP_FAILURE)
```

## 🎯 목표: 모든 진단 결과는 Pain $\rightarrow$ Gain의 드라마를 통해 전달되어야 한다.

### 1. 핵심 원칙
*   **Principle:** 데이터는 수치가 아니라 '변화(Change)'다.
*   **Tone & Manner:** 전문적이고, 동시에 긴장감 넘치는 (Urgent but Optimistic).
*   **기술적 기반:** Codari가 검증한 `Diagnosis_Results` 스키마를 100% 준수한다.

### 2. 컴포넌트 모듈 정의

#### A. [Module: Key Metric Tracker] - 핵심 KPI 변화 추적기 (최우선 적용)
*   **사용처:** 영상 초반(Pain 제시), 중반(솔루션 효과 시뮬레이션).
*   **데이터 바인딩:** `Growth`, `Engagement` 필드 사용.
*   **시각화 방식:** Before/After 슬라이드 애니메이션 (좌측 $\rightarrow$ 우측)
    *   **Before State (Pain):** 수치에 붉은 경고(`#CC0000`)와 함께 "위험", "개선 필요"라는 문구 삽입. (폰트: Montserrat Bold, 크기: Large). 배경색을 Dark Blue를 살짝 벗어난 어두운 회색 계열로 처리하여 위압감 부여.
    *   **Transition:** 수치가 급격히 변하는 듯한 '스윕(Sweep)' 효과 애니메이션 적용.
    *   **After State (Gain):** 수치에 밝은 노란색 강조(`#FFD700`)와 함께 "성장", "확보된 이득" 문구 삽입. 배경을 Neutral Grey로 회복시키며 시각적 안정을 제공.

#### B. [Module: Diagnostic Score Card] - 진단 점수 카드 (Gap Score)
*   **사용처:** 영상 중반부, 솔루션 적용 직후의 결과 요약.
*   **데이터 바인딩:** `diagnosis_type` 및 최종 계산된 Gap Score 사용.
*   **디자인 구조:** 3분할 레이아웃 (`Growth/Engagement/Monetization`).
    *   각 섹션은 독립적인 카드로 구성되며, 점수(%)는 가장 크게 표시된다.
    *   **시그널링:** 점수에 따라 배경색을 동적으로 변경한다. (예: 10% 미만 $\rightarrow$ 경고 Yellow/Red / 20% 이상 $\rightarrow$ 성공 Green).

#### C. [Module: Data Timeline] - 데이터 흐름 시간표
*   **사용처:** 영상 후반부, 전체 로드맵 제시.
*   **데이터 바인딩:** `timestamp` 및 주요 이정표(Milestone)를 시각화.
*   **시각화 방식:** 타임라인 형태로 구성되며, 각 데이터 포인트는 연결된 점과 짧은 애니메이션 트랜지션을 가진다. (기술적 완성도를 보여주는 역할).

### 3. 디자인 가이드 및 참고 사항
1.  **Color Logic:** 모든 강조 색상은 `Accent Yellow (#FFD700)`를 기반으로 하되, Pain 단계에서는 붉은 계열의 채도가 낮은 오렌지-레드(`#E65C4B`)를 사용하여 자극도를 조절한다.
2.  **Typography Hierarchy:** 제목(Pain/Gain)는 항상 Montserrat Bold로 강력한 메시지를 전달하고, 본문 설명과 수치는 Noto Sans KR Regular로 가독성을 확보한다.
