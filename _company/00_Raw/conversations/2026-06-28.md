## III. 핵심 비주얼 컴포넌트 디자인 가이드라인 (Component Design Rules)
각 단계에서 사용되는 주요 요소별 구체적인 스타일을 확정한다.

**1. [진단 그래프] Component:**
*   **애니메이션**: 데이터가 '점(Dot)'으로 시작하여 실시간으로 선이 그려지는 트랜지션 사용. (미스터리함 $\rightarrow$ 객관성).
*   **색상 규칙**: 목표/정상 범위는 **Dark Blue**로 안정감을, 현재 진단된 오차 범위 또는 Gap은 **Accent Yellow**의 경고 톤을 사용하여 시선을 집중시킨다.
*   **레이아웃**: 화면 중앙에 배치하며, X축(시간)과 Y축(Hz) 레이블을 명확히 표시한다.

**2. [Gap Score] Component:**
*   **시각화 방식**: 단순한 숫자가 아닌, '퍼널(Funnel)' 또는 '게이지(Gauge)' 형태로 시각화하여 개선의 여지(Potential)를 직관적으로 보여준다.
*   **텍스트 강조**: "당신은 이 지점에서 $\text{X}$ 만큼 놓치고 있습니다."와 같이 문장형으로 Gap을 설명하고, 수치를 괄호 안에 넣는다.

**3. [CTA/Call to Action] Component:**
*   **최종 CTA (Gain)**: Stage 2에서 사용되며, 크기(Montserrat Bold)가 가장 크고, 배경색은 Dark Blue를 유지하되 **Accent Yellow의 테두리**를 주어 고급스러운 '획득' 느낌을 준다.
*   **경고성 CTA (Pain)**: Stage 0과 1에서 사용되며, Accent Yellow 전용 버튼 형태로, "지금 확인하기"와 같이 긴급성을 부여한다.

import { Request, Response } from 'express'; // Assuming Express framework usage
import { DiagnosisRequestInput, ApiErrorResponse } from '../../types/DiagnosisTypes';
import { calculateDiagnosisScore } from '../../services/DiagnosisService';

/**
 * POST /api/v1/diagnosis_score
 * 클라이언트의 진단 요청을 받아 점수를 계산하고 결과물을 반환합니다.
 * @param req - Express Request 객체 (body에서 DiagnosisRequestInput 추출)
 * @param res - Express Response 객체
 */
export const getDiagnosisScore = async (req: Request, res: Response): Promise<void> => {
    try {
        // 1. 입력 값 유효성 검증 및 데이터 계약 확인
        const inputData: DiagnosisRequestInput = req.body; // 실제 환경에서는 body 파싱이 필요함

        if (!inputData || !inputData.diagnosisType || !inputData.contextId) {

                errorCode: 400,
                message: "Missing required parameters (diagnosisType or contextId)."
            } as ApiErrorResponse);

        const scoreResult = await calculateDiagnosisScore(inputData);

        return res.status(200).json(scoreResult);

        return res.status(500).json({

#### 🥇 A. Pain Point 제시 모듈 (The Problem/Risk - Loss Focus)
*   **목적:** 시청자가 현재 느끼고 있는 문제(Pain)를 구체적인 데이터와 함께 명확히 인지시킵니다.

*   **레이아웃 규칙:** **[헤드라인(Montserrat Bold)]**로 문제 정의 $\rightarrow$ **[데이터 시각화]**로 위험 수치 제시 $\rightarrow$ **[본문 텍스트]**로 심층 분석 설명 (배경: `#F5F5F5`).
*   **필수 요소:** "OOO 점수가 낮은 이유"와 같이 구체적인 *원인 지표(Diagnosis Metric)*를 반드시 강조해야 합니다.

#### 🥈 B. Solution & Mechanism 모듈 (The Process/System - Trust Focus)
*   **목적:** 아지트아트컴페니의 프로그램이나 기술이 어떻게 문제를 해결하는지 논리적으로 설명합니다. (기술 스토리보드 시각화).
*   **비주얼 컨셉:** `#0A2463` (Primary Trust)를 주력으로 사용하여 신뢰감을 구축합니다.
*   **레이아웃 규칙:** **[단계별 플로우차트]** 형태가 가장 효과적입니다. 각 단계는 번호와 화살표로 명확히 구분되어야 하며, 데이터 흐름(Data Flow)이 직관적으로 이해되도록 모듈화합니다. (예: Diagnosis $\rightarrow$ Analysis $\rightarrow$ Improvement).
*   **필수 요소:** API 호출 시퀀스(`Coder`가 제시하는 로직)를 마치 시스템 다이어그램처럼 간결하게 시각화해야 합니다.

#### 🥉 C. Gain Point 확정 모듈 (The Solution/Opportunity - Gain Focus)
*   **목적:** 솔루션을 적용했을 때 얻게 될 '긍정적인 변화'와 '성장 가능성(ROI)'을 극적으로 제시합니다. (클릭 유도 지점).
*   **비주얼 컨셉:** `#FFD700` (Accent CTA)를 가장 많이 사용하며, 대비 효과를 최대화합니다.
*   **레이아웃 규칙:** **[Before $\rightarrow$ After]**의 변화 구도를 명확히 보여줍니다. Before는 Pain 모듈의 결과였던 수치를 배경으로 깔고, After에 `#FFD700`로 '성장 폭'을 크게 강조하는 것이 핵심입니다.
*   **필수 요소:** 모든 콘텐츠의 마지막에는 반드시 **[명확한 CTA]** 버튼이 포함되어야 하며, 이 버튼은 Primary Trust와 Accent CTA를 조합하여 가장 눈에 띄어야 합니다.
