### 🚨 기술적 개선 우선순위 보고 (P0/P1/P2)

#### 🥇 P0: 데이터 무결성 확보 및 스키마 정제 (Schema & Data Consistency)
**[핵심 목표]** 모든 비즈니스 로직의 기반이 되는 데이터를 신뢰할 수 있는 상태로 만듭니다. QA에서 발견된 데이터 불일치 문제를 구조적으로 차단하는 것이 목적입니다.

1.  **`Diagnosis_Results` 스키마 강화:**
    *   **문제점:** 현재 `result_data`가 JSON으로 묶여 있어, 특정 KPI 필드의 유효성 검증(Schema Validation)이 백엔드 단에서 충분하지 않습니다. [근거: sessions/2026-05-18T14-34/developer.md]
    *   **개선 방안:** `Diagnosis_Results` 테이블에 주요 KPI 필드(`growth_score`, `engagement_score`, `monetization_score`)를 JSON 대신 **직접 컬럼으로 분리하고 외래 키(FK) 제약 조건**을 부여합니다. 이를 통해 데이터 쓰기 시점에 타입 및 필수 값 검증이 강제됩니다.
2.  **트랜잭션 경계 명확화:**
    *   **문제점:** 진단 결과 저장 과정에서 여러 테이블(`Diagnosis_Results` $\rightarrow$ `KPI_Metrics`)에 걸쳐 트랜잭션 처리가 완벽하지 않아 일부 데이터만 커밋되고 나머지는 실패하는 상황이 발생할 수 있습니다. [근거: sessions/2026-05-18T43/developer.md]
    *   **개선 방안:** 진단 점수 계산 및 저장 전체를 **하나의 원자적 트랜잭션(Atomic Transaction)**으로 묶어, 모든 과정이 성공하거나 모두 실패하도록 강제합니다.

#### 🥈 P1: 핵심 로직 리팩토링 및 API 계약 재정립 (Core Logic & Contract)
**[핵심 목표]** QA에서 발생한 `UnboundLocalError`와 같은 런타임 에러의 근본 원인(상태 관리 오류, 조건 분기 처리 누락 등)을 제거하고, 모든 외부 호출에 대한 안정적인 API 인터페이스를 만듭니다.

1.  **RBAC 검증 로직 중앙화:**
    *   **문제점:** 권한 체크(`diagnosis_type` 접근 여부)가 여러 곳에 산재되어 있어, 비즈니스 규칙 변경 시 수정 지점이 많고 누락 위험이 높습니다. [근거: sessions/2026-05-18T13:43/developer.md]
    *   **개선 방안:** 진단 API의 **가장 첫 단계(Guard Clause)**에서 사용자 토큰 기반으로 `Role`과 `Diagnosis_Type`에 대한 권한 검증을 수행하는 전용 미들웨어(Middleware)를 구현합니다. 로직 실패 시에는 503 Service Unavailable 응답 코드를 반환하도록 통일합니다.
2.  **점수 계산 파이프라인 분리:**
    *   **문제점:** 점수 계산(`Gap Score` 산출) 로직과 데이터 저장/유효성 검증 로직이 혼재되어 있어, 디버깅이 어렵고 테스트가 불가능한 부분이 많습니다.
    *   **개선 방안:** `calculateDiagnosisScore(inputData)`와 같이 **순수 함수(Pure Function)** 형태로 분리합니다. 이 함수는 오직 입력 데이터만을 받아 점수를 반환하며, DB 접근 같은 사이드 이펙트는 제거하여 테스트 가능성을 극대화합니다.

#### 🥉 P2: 검증 시스템 강화 (Testing & Automation)

## 🎨 시각 자료 제작 지침 (Motion Graphic Style Guide)

이 스크립트의 감정적 흐름(불안 $\rightarrow$ 객관성 $\rightarrow$ 확신)을 시각적으로 뒷받침하기 위한 디자인 가이드입니다. **Designer 에이전트가 이 지침을 바탕으로 실제 애니메이션 및 그래픽 자산을 제작해야 합니다.**

**1. 전체 톤앤매너 (Mood & Tone):**
*   **색상 팔레트:** 차분하고 신뢰감을 주는 블루/그레이 계열을 메인으로 사용하며, 불안정함을 나타낼 때는 강렬한 레드 또는 오렌지 포인트를 사용하여 대비를 극대화합니다. (기술적 안정성과 감성적 연결의 이중성 표현)
*   **애니메이션 스타일:** 미니멀리즘(Minimalism) 기반의 데이터 시각화. 복잡한 개념을 단순하고 명확한 그래프와 인포그래픽으로 즉시 이해할 수 있도록 설계합니다.

**2. 핵심 시각 요소 (Key Visual Elements):**
*   **파형/음정 시각화:** 사용자의 보컬 파형(Waveform)은 불안정할 때는 '깨지거나 떨리는' 질감을, 진단 후에는 '매끄럽고 안정적인' 형태로 변화시켜야 합니다.
*   **Gap Score 시각화:** 점수(예: C-)가 나올 때마다 해당 점수에 맞는 색상과 아이콘이 등장하며, 이 점수가 낮아질수록 (성장할수록) 밝고 긍정적인 색으로 전환되도록 설계합니다.
*   **변곡점 강조:** 'Before'와 'After'의 대비를 보여줄 때, 화면 중앙에 수직선(Vertical Line) 또는 분리선(Divider)을 사용하여 **'변곡점'이 발생하는 지점**을 시각적으로 명확하게 강조해야 합니다.

**3. 텍스트 및 타이포그래피:**
*   **핵심 메시지:** 모든 중요한 데이터 포인트와 핵심 문구는 간결하고 볼드한 산세리프체(Sans-serif)를 사용하여, 복잡한 내용을 빠르게 소화하도록 디자인합니다. (예: "432~450Hz" 같은 수치는 가장 크게 표시).
*   **레이아웃:** 화면을 3분할 또는 2분할 구도로 나누어, 좌측에는 문제(불안), 중앙에는 해결책(AI 시스템), 우측에는 결과(승리)를 배치하여 서사 흐름을 시각적으로 안내합니다.

/**
 * @description 진단 점수 산출 및 DB 로직 처리를 담당하는 서비스 계층 (비즈니스 로직)
 * [WHY] 컨트롤러와 DB 접근 로직을 분리하여 테스트 가능성(Testability) 확보.
 */
import { Pool } from 'pg'; // 가정: PostgreSQL 사용

// 실제 DB 연결 풀 객체는 환경 변수에서 가져온다고 가정합니다.
const pool = new Pool({ connectionString: process.env.DATABASE_URL }); 

/**
 * 사용자 ID와 Context ID를 기반으로 복합적인 진단 점수 및 Gap Score를 산출합니다.
 * @param userId - 현재 로그인한 사용자 ID
 * @param contextId - 진단이 발생한 특정 컨텍스트의 ID (예: 체험 만료 시점)
 * @returns Promise<{ overall_score: number, gap_details: object, recommendation: string }>
 */
export const getDiagnosisScoreService = async (userId: string, contextId: string): Promise<any> => {
    console.log(`[SERVICE] Starting diagnosis score calculation for User ${userId} at Context ${contextId}`);

    // 1. 데이터 검증 및 권한 확인 로직 실행 (DB 트랜잭션 시작 전)
    // 여기서 사용자의 구독 레벨을 조회하여 접근 가능한 진단 타입을 체크합니다. [근거: sessions/2026-05-18T13:43/developer.md]

    // 2. DB에서 필요한 모든 과거 로그 및 KPI 데이터를 가져옵니다.
    const result = await pool.query(`
        SELECT * FROM diagnosis_results dr JOIN kpi_metrics km ON dr.id = km.diagnosis_result_id WHERE dr.context_id = $1 AND dr.user_id = $2;
    `, [contextId, userId]);

    if (result.rows.length === 0) {
        // 데이터가 없으면 최소한의 기본 점수를 반환하거나 에러 처리합니다.
        return { overall_score: 0.0, gap_details: {}, recommendation: "No data found." };
    }

    // 3. 핵심 비즈니스 로직 (Gap Score 계산) 수행 - 이 부분이 가장 복잡함.
    let totalGapScore = 0;
    const gapDetails: any = { growth: 0, engagement: 0, monetization: 0 };

    // 임시로 DB에서 가져온 데이터를 바탕으로 점수 산출 (실제로는 AI/ML 모델이나 정교한 가중치 계산 필요)
    for (const row of result.rows) {
        // 예시 로직: Growth KPI가 낮을수록 성장 Gap이 크다고 가정
        if (row.growth_score < 0.5) {
            gapDetails.growth += (1 - row.growth_score);
        }
    }

    // 최종 점수 합산 및 정규화
    totalGapScore = Math.min(10, gapDetails.growth + gapDetails.engagement + gapDetails.monetization) * 10; // 최대 10점 (가정)


    // 4. DB에 새로운 진단 결과와 Gap Score를 기록합니다. [근거: sessions/2026-05-18T43/developer.md]
    const writeResult = await pool.query(`
        INSERT INTO diagnosis_results (user_id, context_id, gap_score, ...) 
        VALUES ($1, $2, $3) RETURNING *;
    `, [userId, contextId, totalGapScore]);


    // 5. 최종 결과 반환
    return {
        overall_score: parseFloat(totalGapScore.toFixed(2)),
        gap_details: gapDetails,
        recommendation: `차별화된 맞춤 학습 플랜을 제공합니다. (${totalGapScore > 7 ? 'PREMIUM' : 'FREE'})`
    };
};
