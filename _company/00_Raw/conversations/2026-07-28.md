# 🎬 최종 Motion Graphic Style Guide (V1.0)
**프로젝트:** 실용음악 AI 활용 프로그램 교육 콘텐츠
**목표:** 시청자에게 '추상적 노력'이 아닌 '측정 가능한 데이터 기반의 과학적인 해결책'이라는 권위를 각인시킨다.

## 🌟 1. 핵심 디자인 원칙 (The Philosophy)
*   **Pain $\rightarrow$ Gain 서사 적용:** 모든 애니메이션은 먼저 *문제점(Pain)*을 시각적으로 증폭시키고, 그 다음 *솔루션/해결책(Gain)*이 등장하며 문제를 해결하는 구조를 가져야 합니다.
    *   (예시) 불안정한 음파 $\rightarrow$ Gap Score 분석 $\rightarrow$ 명확한 훈련 지점 제시 (Yellow 강조).
*   **미니멀리즘 데이터 중심:** 배경은 최대한 깔끔하게 유지하고, 오직 **데이터 그래프와 핵심 수치**에만 모든 시각적 에너지를 집중시킵니다.
*   **속도감과 전문성:** 전환(Transition) 효과는 빠르고 기계적인 느낌을 주어, '학문적/과학적 분석'이라는 인상을 강화합니다.

## 🎨 2. 색상 및 타이포그래피 규정 (Visual Assets)

| 요소 | 컬러 코드 | 역할 및 사용처 | 애니메이션 지침 |
| :--- | :--- | :--- | :--- |
| **Primary Trust** (신뢰) | `#0A2463` (Dark Blue) | 배경의 메인 컬러, 그래프의 기준선(Ideal Line), 헤더/CTA의 기본 톤. 전문성 확보. | 부드럽고 안정적으로 등장하며, 고정된 영역을 구축합니다. |
| **Accent Yellow** (기회/위험) | `#FFD700` (Yellow) | Gap Score의 '차이' 강조, Pain Point(문제), 핵심 수치 변화(Gain). 시선 집중 유도. | *깜빡임 효과*, 경고음과 동기화된 **강렬한 팝업** 애니메이션 필수. |
| **Neutral Grey** (배경/데이터) | `#F5F5F5` (Grey) | 그래프 배경, 데이터 테이블의 셀 배경. Dark Blue와의 명확한 대비 유지. | 최소한의 움직임만 가집니다. 배경 역할을 합니다. |
| **Title Font** (헤드라인) | Montserrat Bold | 영상 내 핵심 질문, 문제 제기 문구(Pain/Gain). 임팩트 극대화. | **Typewriter Effect** 또는 *Scale Up*으로 등장하여 강력함을 전달합니다. |
| **Body Font** (데이터/설명) | Noto Sans KR Regular | 그래프 축 레이블, 데이터 수치, 상세 설명 텍스트. 가독성 최우선. | 부드러운 **Fade-In**과 함께 순차적으로 나타납니다 (읽기 흐름). |

## 📈 3. 핵심 컴포넌트: Gap Score 시각화 명세서
Gap Score는 이 채널의 가장 중요한 지적 재산입니다. 별도의 애니메이션 규칙이 필요합니다.

1.  **[기준선 설정]**: 항상 `Dark Blue (#0A2463)`로 '이상적인 값' 또는 '목표치'를 나타내는 가이드 라인을 먼저 그립니다 (Static Line).
2.  **[현재 측정값]**: 실제 측정한 음파/발성 주파수 그래프는 `#FFD700`으로 표시합니다. 이는 현재의 상태이자 개선이 필요한 영역입니다.
3.  **[Gap 발생 애니메이션]**:
    *   그래프가 완성된 후, `Dark Blue` 기준선과 `Yellow` 측정값 사이의 **'틈새(Gap)'**에만 `#FFD700`을 덧입혀 강조합니다 (Overlay Animation).
    *   이 Gap 영역은 잠시 동안 확대되거나 깜빡이며 '여기에 문제가 있다'는 시각적 경고를 주어야 합니다.

## 📜 4. 애니메이션 및 전환 규칙 (Motion Guidelines)
| 상황 | 지침 | 효과/속도 | 목적 |
| :--- | :--- | :--- | :--- |
| **데이터 그래프 생성** | 축(Axis)부터 순차적으로 데이터를 그려나갑니다. | 트레이싱(Tracing) 또는 플롯팅(Plotting). 빠르지만 부드럽게 (2~3초). | 데이터가 '발견'되고 '분석'되는 과정을 보여주어 신뢰도를 높입니다. |
| **핵심 수치 강조** | 중요한 숫자가 등장할 때마다 사용합니다. | *Scale-Up* 후 `#FFD700`으로 채색 및 미세한 떨림(Jitter) 효과 부여. | 시청자의 눈을 강제로 유도하여 '이게 핵심이다'라는 인상을 줍니다. |
| **전환 (Transition)** | A 개념에서 B 개념으로 넘어갈 때 사용합니다. | *데이터 흐름 전환*: 화면 전체가 Blue/Yellow의 파형 그래프로 잠시 변했다가, 다음 장면의 구조적 레이아웃으로 부드럽게 재구성됩니다. (지루한 '화면 전환' 금지). | 콘텐츠가 끊어지지 않고 유기적으로 연결되는 느낌을 줍니다. |
| **텍스트 강조** | 핵심 키워드가 등장할 때만 사용합니다. | `Montserrat Bold`의 단어에 순간적인 *Flash* 효과를 주고, `#FFD700`으로 채색합니다. | 메시지의 중요도를 극대화합니다. |

### 🚀 최종 액션 플랜: 비즈니스 우선순위 기반 로드맵 조정

기술적 안정성은 필수지만, 개발 리소스는 한정되어 있습니다. 따라서 코다리의 작업 범위를 다음과 같이 재조정하여 **최대 매출 기여도(High ROI)**를 목표로 합니다.

**[재조정된 개발 로드맵: 3단계 접근]**

1.  **Phase 0 (Critical Foundation - P0): 시스템 신뢰성 구축**
    *   **목표:** 진단 데이터의 '무결성' 확보 및 사용자 경험 중단을 막는 것.
    *   **주요 작업:** `Diagnosis_Results` 스키마 수정(JSON 강제 검증), 핵심 트랜잭션 로직 안정화 (API/DB).
    *   **비즈니스 결과 예측:** 'Gap Score 진단 테스트'의 신뢰도가 확보되어, 사용자에게 **실질적인 구매 동기**를 제공할 수 있게 됩니다.

2.  **Phase 1 (Monetization Gate - P1): 유료 전환 장치 구축**
    *   **목표:** 사용자가 '기술적으로 다음 단계로 나아갈 수 없게' 만드는 시스템적 제어 장치를 마련하는 것.
    *   **주요 작업:** 권한 로직 분리 및 강화 (유료 모듈 접근 제한), 결제 관련 API와 진단 결과 연동 테스트 완료.
    *   **비즈니스 결과 예측:** '무료 체험'이 명확히 끝나고, **구독 전환을 위한 강력하고 자연스러운 CTA(Call to Action)**가 작동합니다.

3.  **Phase 2 (Polish & Scale - P2): 사용자 여정 최적화**
    *   **목표:** 오류 발생 시의 '사용자 감정'까지 고려하여 매끄러운 경험을 제공하는 것.
    *   **주요 작업:** 일반적인 에러 핸들링 및 UX 피드백 개선.
    *   **비즈니스 결과 예측:** 이 단계가 완료되면 제품이 *MVP* 단계를 벗어나 시장에 성공적으로 출시할 수 있는 **'상품화된 서비스'**로 진입합니다.

## 📐 P0 핵심 컴포넌트별 디자인 요구사항 업데이트

### 1. 진단 결과 리포트 카드 (Diagnosis Result Card)
(기술적 개선 사항 반영: 데이터 무결성 및 버전 관리 시스템 도입)

| 요소 | 디자인 규칙 | 기술 구현 시 고려사항 | 예시/사용처 |
| :--- | :--- | :--- | :--- |
| **전체 구조** | 배경: Neutral Grey (`#F5F5F5`). 경계선(Border): Light Blue (옅은 파란색). | 결과 로딩 완료 시, 데이터 무결성 검증을 마쳤다는 느낌을 주도록 부드러운 애니메이션 효과 필수. | 최종 리포트 페이지 전체 영역 |
| **Gap Score 표시** | 수치: Montserrat Bold / 색상: Dark Blue (`#0A2463`). 하이라이팅: Accent Yellow (`#FFD700`)를 사용하여 '가장 큰 격차'에 시선 집중. | 데이터 버전(e.g., v1.2)을 명시적으로 표시하여, 결과의 신뢰도를 높여야 합니다. (예: `Gap Score V1.2`). | 리포트 최상단 요약 섹션 |
| **데이터 무결성 배지** | 위치: Gap Score 옆 또는 우측 상단 Corner에 배치. 스타일: 작은 캡슐형(Pill-shaped) Badge. 색상: Primary Green (`#4CAF50`) (새로운 신뢰 요소). | 백엔드에서 데이터 트랜잭션이 성공적으로 완료되고 스키마 검증을 통과했을 때만 표시되어야 합니다. **[기술적 필수]** | Gap Score 근처 |
| **데이터 출처 명시** | 폰트: Noto Sans KR (Regular). 색상: Dark Blue의 70% 농도(옅은 파란색)를 사용하여 주 내용을 방해하지 않게 처리. | '근거 데이터', '분석 기준' 등 데이터가 생성된 원천 정보를 하단에 작게 명시하여 투명성을 극대화합니다. | 리포트 하단 Footer 영역 |

### 2. 유료 전환 구간 (The Funnel Gatekeeper)
(기술적 개선 사항 반영: 권한 및 모듈 로직 분리, 수익 모델 보호)

| 요소 | 디자인 규칙 | 기술 구현 시 고려사항 | 예시/사용처 |
| :--- | :--- | :--- | :--- |
| **진단 결과 제한 안내** | 문구: '더 깊이 있는 분석을 위해서는 코칭 패키지가 필요합니다.' (강한 메시지 전달). 배경은 Dark Blue를 사용하여 전문성을 유지하되, 경고 느낌을 부여. | 기술적으로 접근 불가 상태일 때 (Access Denied), 일반적인 에러 메시지 대신 이 **'페르소나화된 안내 문구'**가 노출되어야 합니다. [기술적 필수] | 유료 기능 진입 시점의 모달 또는 섹션 전체 |
| **CTA 버튼 (구매)** | 크기: 화면 폭의 80% 이상 차지하는 거대한 직사각형. 배경색: Accent Yellow (`#FFD700`). 텍스트: Dark Blue (`#0A2463`). | 마우스 오버(Hover) 시, 색상이 약간 어두워지거나 (Darken effect), 미세한 애니메이션 효과를 주어 클릭을 유도해야 합니다. | 패키지 구매 버튼 |
| **'다음 단계' 제시** | CTA 위에 작은 텍스트로 '지금 [서비스 이름]으로 다음 단계를 시작하세요!'와 같은 문구를 배치하여, 사용자가 무엇을 해야 하는지 명확히 안내합니다. | 단순히 결제 버튼만 두는 것이 아니라, 반드시 동기 부여성 카피가 필요합니다. | 구매 CTA 직전의 공간 |

### 3. 상태 메시징 시스템 (State Messaging System)
(기술적 개선 사항 반영: 트랜잭션 경계 및 로직 안정화)

개발팀은 사용자에게 성공/실패/처리 중의 세 가지 상태를 명확하게 시각적으로 인지시켜야 합니다.

| 상태 | UI 요소 | 디자인 규칙 | 개발 구현 지침 |
| :--- | :--- | :--- | :--- |
| **✅ Success (성공)** | 메시지 바 / 토스트 알림 | 배경: Light Green (`#E8F5E9`). 아이콘: 체크 마크(✓). 문구: '진단 결과가 성공적으로 저장되었습니다.' 등 명확한 긍정 피드백. | 트랜잭션 완료 직후, 즉시 사라지도록(Timeout) 구현합니다. |
| **⚠️ Warning (경고)** | 메시지 바 / 알림창 | 배경: Accent Yellow (`#FFF3E0`). 아이콘: 삼각형 경고 마크(!). 문구: '데이터를 다시 확인해 주세요.' 등 사용자의 재확인을 요구할 때 사용. | 사용자 액션(Action)을 유도하며, 페이지의 특정 요소를 강조합니다. |
| **❌ Error (실패)** | 모달 창 / 메시지 바 | 배경: Red 계열 (`#FFEBEE`). 아이콘: X 마크(✕). 문구: "시스템 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." (전문적이고 차분한 톤 유지) | **절대 기술 용어(UnboundLocalError 등)를 노출하지 않습니다.** 사용자에게는 일반적인 '서비스 이용 불가'로만 전달합니다. [기술적 필수] |
