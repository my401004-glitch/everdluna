## 📋 ✨ [개발 요청] Potential ROI (pROI) 통합 요구사항 목록

코다리 개발자님께 다음 세 가지 핵심 영역에 대한 구현을 요청드립니다.

### 📊 1. 데이터 모델링 및 스키마 수정 (DB Schema Update)
기존의 사용자 프로필/진단 결과 테이블(`User` 또는 `DiagnosisResult`)에 아래 필드들을 추가하고, 이 데이터를 구조화하여 저장해야 합니다.

*   **[핵심 지표] pROI 점수:** 최종 계산된 Potential ROI 값을 저장할 `FLOAT` 타입 필드 (예: `user_potential_roi`).
*   **[Gap Score 관련] GSM 구성 데이터:** Gap Score를 산출하는 근거가 되는 3가지 핵심 성능 지표를 각각 기록합니다.
    *   `pitch_deviation_index`: 평균 음정 편차 값.
    *   `breath_efficiency_score`: 호흡 효율 점수 (목표 대비 부족 공기압률).
    *   `emotional_consistency_score`: 감정 표현 일관성 점수.
*   **[Engagement Value 관련] EVS 추적 데이터:** 참여 가치를 계산하기 위한 사용자의 활동 기록을 연결합니다.
    *   `test_attempts`: 진단 테스트 시도 횟수 (Int).
    *   `module_view_rate`: 무료 제공 모듈 완료율/진행률 (Float 또는 JSON 형태의 Progress Tracker).

### 📡 2. API 엔드포인트 설계 및 수정 (API Endpoint Re-design)
현재 존재하는 진단 관련 API들을 확장하거나, 새로운 계산 전용 엔드포인트를 추가해야 합니다.

*   **A. `diagnosis_score` 엔드포인트 확장:**
    *   기존: 점수(Score)만 반환.
    *   수정 요청: **GSM의 3가지 구성 요소 값과 EVS 추적 데이터까지 모두 JSON 형태로 함께 응답하도록 수정**해야 합니다. (전체 계산 근거를 프론트엔드에 노출하기 위함).
*   **B. 신규 엔드포인트 생성 (`/api/user/potential-roi`):**
    *   목표: 사용자가 자신의 잠재적 가치를 확인하는 페이지 전용 API입니다.
    *   기능: 사용자 ID를 받아, **저장된 모든 GSM 및 EVS 데이터를 바탕으로 pROI 점수를 재계산하여 반환**해야 합니다. (실시간 계산 기능 필요)

### 📝 3. 비즈니스 로직 구현 상세 정의 (Backend Logic Implementation)
개발자가 직접 코딩해야 할 핵심 수학적/논리적 규칙을 명확히 문서화합니다.

*   **pROI 계산 함수:** `(GSM의 가중치 합 + EVS 점수) / CAC` 공식을 기반으로 하는 Python 또는 백엔드 언어의 전용 계산 모듈을 작성해야 합니다.
    *(💡 중요: 이 pROI 계산 로직은 시스템의 핵심 지적재산(IP)이므로, 별도의 버전 관리 및 테스트가 필요합니다.)*
