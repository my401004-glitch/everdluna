# 🎨 최종 비주얼 시스템 가이드라인 v2.0 (개발팀 전달용)
## 🎯 목적 및 범위

본 가이드는 코다리가 재정의한 P0 핵심 기능(진단 점수 계산, 결과 데이터 무결성 확보, 유료/무료 권한 검증 로직)을 기반으로 합니다. 모든 UI 컴포넌트와 리포트가 다음 원칙에 따라 설계되어야 합니다: **'데이터 신뢰성 시각화 $\rightarrow$ 행동(CTA) 명확화'**

## 🎨 핵심 브랜드 에셋 재정의 (변경 없음)

| 요소 | 정의/코드 | 사용 목적 및 강조점 |
| :--- | :--- | :--- |
| **Primary Color (Trust)** | Dark Blue (`#0A2463`) | 신뢰성, 전문성. 헤더, 배경, 핵심 데이터 섹션에 사용하여 서비스의 권위와 안정감을 부여합니다. [근거: Designer 검증된 지식] |
| **Accent Yellow (Action/Gain)** | Accent Yellow (`#FFD700`) | 기회 포착, 위험 경고(Pain), 최종 CTA. 사용자가 '지금 행동해야 한다'는 직관적 신호를 전달합니다. [근거: Designer 검증된 지식] |
| **Neutral Grey (Background)** | Neutral Grey (`#F5F5F5`) | 데이터 영역 배경. Dark Blue와의 대비를 통해 가독성을 극대화하고, 진단 결과의 명확한 경계를 만듭니다. [근거: Designer 검증된 지식] |
| **Title Typography** | Montserrat Bold | 강력한 헤드라인(Pain/Gain) 강조. 핵심 수치나 메시지를 가장 먼저 읽게 합니다. [근거: Designer 검증된 지식] |
| **Body Typography** | Noto Sans KR (Regular/Medium) | 상세 데이터, 설명 텍스트. 높은 가독성을 유지합니다. [근거: Designer 검증된 지식] |

## 📐 P0 핵심 컴포넌트별 디자인 요구사항 업데이트

### 1. 진단 결과 리포트 카드 (Diagnosis Result Card)
(기술적 개선 사항 반영: 데이터 무결성 및 버전 관리 시스템 도입)

| 요소 | 디자인 규칙 | 기술 구현 시 고려사항 | 예시/사용처 |
| :--- | :--- | :--- | :--- |
| **전체 구조** | 배경: Neutral Grey (`#F5F5F5`). 경계선(Border): Light Blue (옅은 파란색). | 결과 로딩 완료 시, 데이터 무결성 검증을 마쳤다는 느낌을 주도록 부드러운 애니메이션 효과 필수. | 최종 리포트 페이지 전체 영역 |
| **Gap Score 표시** | 수치: Montserrat Bold / 색상: Dark Blue (`#0A2463`). 하이라이팅: Accent Yellow (`#FFD700`)를 사용하여 '가장 큰 격차'에 시선 집중. | 데이터 버전(e.g., v1.2)을 명시적으로 표시하여, 결과의 신뢰도를 높여야 합니다. (예: `Gap Score V1.2`). | 리포트 최상단 요약 섹션 |
| **데이터 무결성 배지** | 위치: Gap Score 옆 또는 우측 상단 Corner에 배치. 스타일: 작은 캡슐형(Pill-shaped) Badge. 색상: Primary Green (`#4CAF50`) (새로운 신뢰 요소). | 백엔드에서 데이터 트랜잭션이 성공적으로 완료되고 스키마 검증을 통과했을 때만 표시되어야 합니다. **[기술적 필수]** | Gap Score 근처 |
| **데이터 출처 명시** | 폰트: Noto Sans KR (Regular). 색상: Dark Blue의 70% 농도(옅은 파란색)를 사용하여 주 내용을 방해하지 않게 처리. | '근거 데이터', '분석 기준' 등 데이터가 생성된 원천 정보를 하단에 작게 명시하여 투명성을 극대화합니다. | 리포트 하단 Footer 영역 |

### 2. 유료 전환 구간 (The Funnel Gatekeeper)
(기술적 개선 사항 반영: 권한 및 모듈 로직 분리, 수익 모델 보호)

| 요소 | 디자인 규칙 | 기술 구현 시 고려사항 | 예시/사용처 |
| :--- | :--- | :--- | :--- |
| **진단 결과 제한 안내** | 문구: '더 깊이 있는 분석을 위해서는 코칭 패키지가 필요합니다.' (강한 메시지 전달). 배경은 Dark Blue를 사용하여 전문성을 유지하되, 경고 느낌을 부여. | 기술적으로 접근 불가 상태일 때 (Access Denied), 일반적인 에러 메시지 대신 이 **'페르소나화된 안내 문구'**가 노출되어야 합니다. [기술적 필수] | 유료 기능 진입 시점의 모달 또는 섹션 전체 |
| **CTA 버튼 (구매)** | 크기: 화면 폭의 80% 이상 차지하는 거대한 직사각형. 배경색: Accent Yellow (`#FFD700`). 텍스트: Dark Blue (`#0A2463`). | 마우스 오버(Hover) 시, 색상이 약간 어두워지거나 (Darken effect), 미세한 애니메이션 효과를 주어 클릭을 유도해야 합니다. | 패키지 구매 버튼 |
| **'다음 단계' 제시** | CTA 위에 작은 텍스트로 '지금 [서비스 이름]으로 다음 단계를 시작하세요!'와 같은 문구를 배치하여, 사용자가 무엇을 해야 하는지 명확히 안내합니다. | 단순히 결제 버튼만 두는 것이 아니라, 반드시 동기 부여성 카피가 필요합니다. | 구매 CTA 직전의 공간 |

### 3. 상태 메시징 시스템 (State Messaging System)
(기술적 개선 사항 반영: 트랜잭션 경계 및 로직 안정화)

개발팀은 사용자에게 성공/실패/처리 중의 세 가지 상태를 명확하게 시각적으로 인지시켜야 합니다.

| 상태 | UI 요소 | 디자인 규칙 | 개발 구현 지침 |
| :--- | :--- | :--- | :--- |
| **✅ Success (성공)** | 메시지 바 / 토스트 알림 | 배경: Light Green (`#E8F5E9`). 아이콘: 체크 마크(✓). 문구: '진단 결과가 성공적으로 저장되었습니다.' 등 명확한 긍정 피드백. | 트랜잭션 완료 직후, 즉시 사라지도록(Timeout) 구현합니다. |
| **⚠️ Warning (경고)** | 메시지 바 / 알림창 | 배경: Accent Yellow (`#FFF3E0`). 아이콘: 삼각형 경고 마크(!). 문구: '데이터를 다시 확인해 주세요.' 등 사용자의 재확인을 요구할 때 사용. | 사용자 액션(Action)을 유도하며, 페이지의 특정 요소를 강조합니다. |
| **❌ Error (실패)** | 모달 창 / 메시지 바 | 배경: Red 계열 (`#FFEBEE`). 아이콘: X 마크(✕). 문구: "시스템 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." (전문적이고 차분한 톤 유지) | **절대 기술 용어(UnboundLocalError 등)를 노출하지 않습니다.** 사용자에게는 일반적인 '서비스 이용 불가'로만 전달합니다. [기술적 필수] |
