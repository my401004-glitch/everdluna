### I. 프로젝트 종류 및 아키텍처 정의 (Project Definition)

우리가 구축하려는 것은 단순한 웹사이트가 아니라, AI 진단 데이터를 기반으로 사용자 성장을 추적하고 유료 전환을 유도하는 **데이터 중심의 SaaS 플랫폼**입니다. 따라서 다음 구조로 프로젝트를 정의합니다.

*   **프로젝트 유형:** AI 기반 성장 데이터 분석 및 관리 시스템 (SaaS Dashboard)
*   **핵심 목표:** 실용음악 학습자의 성과 데이터를 시각화하고, 이를 통해 학원 운영자에게 ROI 기반의 가치를 제공하는 백엔드/프론트엔드 시스템 구축.
*   **권장 키트 선택:** `dashboard-kit` (SaaS 및 관리자 대시보드 기능이 핵심 목표와 가장 잘 부합합니다.)

### II. 초기화 계획 초안 (Initialization Plan Draft)

다음은 `web_init`을 실행하기 위해 필요한 최소한의 구조 설계입니다. 이 설계를 바탕으로 실제 파일 생성을 진행하겠습니다.

#### 1. 데이터베이스 스키마 정의 (DB Schema Definition)
KPI 추적과 RBAC(권한 기반 접근 제어)를 반영하여 핵심 테이블을 먼저 정의합니다. 이는 백엔드 로직 구현의 근간이 됩니다.

*   **테이블 명:** `Users`, `Diagnosis_Results`, `KPI_Metrics`
*   **핵심 관계:** 사용자는 진단 결과와 KPI 메트릭에 연결되어야 합니다.

#### 2. 백엔드 API 설계 (API Endpoint Outline)
프론트엔드가 데이터를 요청할 수 있도록 필요한 엔드포인트를 정의합니다.

*   `/api/auth`: 로그인, 인증 관련 엔드포인트
*   `/api/diagnose`: AI 진단 테스트 실행 및 결과 저장
*   `/api/metrics`: 사용자별 성장 지표(Growth, Engagement, Monetization) 조회

#### 3. 파일 구조 제안 (File Structure Proposal)
Next.js 기반의 풀스택 프로젝트를 가정하고 표준적인 구조를 제시합니다.

```
/PROJECT_PATH (예: /Users/iyeongjae/Desktop/초보프로젝트/music_growth_saas)
├── /public                 # 정적 파일 (이미지, 폰트 등)
├── /src
│   ├── /app              # Next.js App Router 구조
│   │   ├── /api         # 백엔드 API 핸들러
│   │   ├── /dashboard  # 대시보드 컴포넌트
│   │   └── /lib        # 공통 유틸리티 및 DB 연결 로직
│   └── /types           # TypeScript 타입 정의 파일
├── .env                  # 환경 변수 설정 (API 키, DB 접속 정보)
├── package.json
└── tsconfig.json
```
