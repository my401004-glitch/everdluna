## II. 시스템 상태 컴포넌트 (State Components) 사양

### 1. Loading State Component (`<Loading />`)
*   **목적:** 데이터 로딩 중임을 사용자에게 알리고, 대기 시간을 지루하지 않게 만듭니다.
*   **시각적 정의:** 단순한 스피너가 아닌, **'데이터 수집 및 분석 중'**이라는 전문적인 느낌을 주어야 합니다.
    *   **구성:** `[로딩 메시지]` + `[애니메이션 로더]`
    *   **텍스트 예시 (Body Type):** "AI 모델이 사용자 데이터를 학습하고 있습니다. 잠시만 기다려주세요."
    *   **모션 사양 (Leo 협력 필수):** 3~5초의 적절한 로딩 시간을 가정하며, 스피너는 원형 트랙을 따라 부드럽게 회전해야 합니다. 로더가 활성화되는 순간과 비활성화되는 순간 모두 `ease-out` 이징을 적용하여 급격한 변화를 방지합니다.
    *   **구현 팁:** '점멸하는' 느낌보다는, 데이터 흐름이 막히고 풀리는 듯한 **흐르는(Flowing)** 애니메이션이 선호됩니다.

### 2. Error State Component (`<Error />`)
*   **목적:** 시스템 오류나 사용자 입력 오류를 명확하게 알리고 해결책을 제시합니다. (Pain 강조)
*   **시각적 정의:** 경고성을 극대화하되, 패닉하지 않도록 신뢰감 있는 톤을 유지해야 합니다.
    *   **구성:** `[Alert Red 테두리 박스]` + `[에러 아이콘]` + `[구체적인 오류 메시지 (Noto Sans KR)]` + `[해결 방법/CTA 버튼]`
    *   **오류 유형 예시:**
        *   *Input Error:* "입력하신 값이 유효하지 않습니다. [필수 항목]을 다시 확인해주세요."
        *   *System Error:* "데이터 전송에 실패했습니다. 네트워크 연결 상태를 확인하거나 1분 후 다시 시도해 주세요."
    *   **모션 사양 (Leo 협력 필수):** 에러 박스는 부드럽게 페이드인(Fade-in)되어야 합니다. 에러 메시지(Pain)가 화면에 나타날 때는 `shake` 애니메이션보다는, 경고음과 함께 텍스트가 순차적으로 강조되는 방식이 효과적입니다.

### 3. Disabled State Component (`<Disabled />`)
*   **목적:** 현재 상호작용할 수 없는 요소를 시각적으로 비활성화하여 오사용을 방지합니다.
*   **시각적 정의:** 색상과 투명도를 사용하여 '비활동 상태'임을 명확히 합니다. (Pain 최소화)
    *   **색상 사양:** `Primary Color`의 채도를 낮추고, 불투명도(Opacity)를 40%로 설정합니다.
    *   **커서 변화:** 마우스를 올렸을 때(`:hover`) 커서를 포인터에서 기본 화살표 모양으로 변경하여 상호작용 불가 상태임을 인지시킵니다.

## III. 컴포넌트 구조 가이드라인 (개발팀 필독)
1.  **컴포넌트 명명 규칙:** 모든 컴포넌트는 BEM(Block Element Modifier) 또는 유사한 시스템적 네이밍 컨벤션을 따릅니다. 예: `Button--is-loading`, `Card__state--error`.
2.  **데이터 흐름 우선:** 상태 변화는 반드시 **[진단 결과 $\rightarrow$ 문제점 인식 $\rightarrow$ 해결책 제시 (CTA)]**의 논리적 흐름을 깨지 않아야 합니다. 로딩 중일 때도 사용자는 '왜 기다려야 하는가?'에 대한 맥락적 이해를 해야 합니다.
3.  **반응형(Responsive):** 모든 상태 컴포넌트는 모바일, 태블릿, 데스크톱 환경에서 일관된 계층 구조와 시각적 위계를 유지해야 합니다.
