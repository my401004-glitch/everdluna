## 💡 'Pain $\rightarrow$ Gain' 유료 전환 흐름 최종 UX/Visual 검증 체크리스트 (v1.0)

**목표:** 주관적 노력(Pain) $\xrightarrow{\text{데이터 증명}}$ 객관적 통찰(Solution) $\xrightarrow{\text{시각화}}$ 행동 의지 및 구매(Gain).

### 📊 섹션 A: Pain Point 극대화 (Hook & Frustration)
*이 단계의 목표는 사용자가 스스로 '문제'가 있다는 것을 느끼게 하는 것입니다. 추상적 불안감을 데이터로 구체화하는 것이 핵심입니다.*

| # | 검증 항목 | 세부 시각/감성 요구사항 | 디자인 체크 (Pass/Fail) | 개발 체크 (Dev Status) |
| :---: | :--- | :--- | :---: | :---: |
| **A-1** | **초기 감정적 톤 설정** | 화면 전체가 어둡고 답답한 느낌을 주어야 함. 배경에 약간의 노이즈나 흔들림(Distortion) 효과를 적용하여 불안감을 유도해야 함. [근거: Pain Point 극대화] | | |
| **A-2** | **문제 인지 (Gap Score)** | '노력'과 '결과' 사이의 간극을 시각적으로 표현할 때, 막연한 문구 대신 구체적인 수치(Hz)를 사용해야 함. 이 수치는 항상 *이상적인 값* 대비 *위험 범위*에 있어야 함. [근거: Designer 검증된 지식] | | |
| **A-3** | **컬러 경고 (Pain)** | Gap Score가 위험 수준일 때, 배경이나 텍스트 일부에만 Accent Yellow (`#FFD700`)를 사용하되, 이것이 '경고' 신호처럼 느껴지게 해야 함. 너무 밝으면 CTA로 오인함. [근거: Designer 검증된 지식] | | |
| **A-4** | **좌절감의 시각화** | 일반적인 코칭 방식(예: 호흡법)을 설명할 때, 그 방식이 *왜 작동하지 않는지*를 데이터 기반으로 반박하는 비주얼 요소가 포함되어야 함. (ex. '호흡'에 대한 물리적 근거 제시 실패). [근거: Writer 스크립트] | | |

### 📈 섹션 B: 신뢰 구축 및 해결책 제시 (Data & Authority)
*이 단계의 목표는 감정적 혼란을 객관적인 데이터로 대체하여 '이 시스템은 나를 믿을 만하다'는 확신을 주는 것입니다.*

| # | 검증 항목 | 세부 시각/감성 요구사항 | 디자인 체크 (Pass/Fail) | 개발 체크 (Dev Status) |
| :---: | :--- | :--- | :---: | :---: |
| **B-1** | **데이터의 전문성 확보** | 진단 결과 그래프나 수치 변화는 복잡하지만, 구조적이고 깔끔해야 함. 다크 블루 (`#0A2463`)를 배경과 주요 축에 사용하여 '전문 연구기관' 같은 느낌을 주어야 함. [근거: Designer 검증된 지식] | | |
| **B-2** | **명확한 원인 제시** | "당신의 문제는 노력 부족이 아니라, *이것* 때문입니다"라는 메시지가 나올 때, 문제의 원인을 가리키는 시각적 포커싱(Spotlight) 효과가 필수임. [근거: Pain $\rightarrow$ Gain 프레임워크] | | |
| **B-3** | **솔루션의 구체화 (Action Item)** | 해결책을 제시할 때, "열심히 하세요"와 같은 모호한 조언이 아닌, '어떤 주파수를', '얼마나 오랫동안' 해야 하는지 등 *명확하고 측정 가능한 행동 지침*이 데이터 형태로 제공되어야 함. [근거: Designer 검증된 지식] | | |
| **B-4** | **기술적 신뢰성 강조** | 시스템의 작동 원리(Algorithm Flow)를 간단한 다이어그램으로 보여주어, "우리가 추측하는 것이 아니라, *과학적으로* 진단한다"는 메시지를 강화해야 함. (도식화 필수). [근거: Designer 검증된 지식] | | |

### ✅ 섹션 C: 전환 및 행동 유도 (Gain & CTA)
*이 단계의 목표는 '나를 변화시킬 수 있다'는 희망(Hope)을 확신(Confidence)으로 바꾸고, 즉각적인 구매 결정으로 이어지게 하는 것입니다.*

| :---: | :--- | :--- | :---: | :---: |
| **C-1** | **변화의 임팩트** | Pain 단계에서 배경이 어둡고 혼란스러웠다면, Gain 단계에서는 밝고 명쾌한 느낌으로 전환되어야 함. 시각적 대비가 극대화되어야 함. [근거: Pain $\rightarrow$ Gain 프레임워크] | | |

| **C-4** | **최종 요약 (Summary)** | 모든 과정이 지나간 후, 사용자가 가장 중요하게 기억해야 할 '핵심 수치(Key Metric)'나 '변화된 목표'를 한눈에 정리해주는 섹션이 필요함. [근거: 데이터 증명형 서사] | | |
