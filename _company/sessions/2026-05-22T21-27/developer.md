### ⚙️ 오디오 데이터 파이프라인: 기술 스펙 및 Man-Day 추정 (MVP 기준)

오디오 처리 과정은 단순 파일 업로드가 아니라, 실시간/비실시간 신호 처리가 필요한 복합적인 백엔드 시스템입니다. 이를 **3개의 핵심 마일스톤**으로 나누어 분리하는 것이 안정적입니다.

#### 1️⃣ Phase I: 오디오 데이터 수집 및 전처리 모듈 (기술 난이도: 중상)
*   **목표:** 사용자가 녹음한 원본 오디오 파일(WAV/MP3)을 받아서, 진단 로직에 사용할 표준화된 형태의 Feature Vector로 변환합니다.
*   **핵심 기술 스택:** Python (Librosa, SciPy 등 DSP 라이브러리 활용), FastAPI 엔드포인트 구축.
*   **세부 작업 및 예상 소요 시간:**
    1.  **파일 업로드 API 정의 및 구현:** 파일 형식 유효성 검사, 전송 용량 제한, 저장소(S3/DB Blob) 연동. (0.5 Man-Day)
    2.  **샘플링 및 리샘플링 파이프라인 구축:** 다양한 입력 포맷을 표준 샘플 레이트(예: 16kHz)로 통일하는 로직 구현. **[주의: 이 단계의 일관성이 가장 중요합니다.]** (1 Man-Day)
    3.  **Feature Extraction 로직 설계 및 테스트:** 피치(Pitch), 주파수 안정성(Frequency Stability), 에너지 레벨 등 핵심 지표 추출 알고리즘 구현 및 단위 테스트 작성. (2 Man-Days)
*   **총 예상 소요 시간: 3.5 ~ 4 Man-Days**

#### 2️⃣ Phase II: 진단 로직 통합 및 백엔드 API 구축 (기술 난이도: 중)
*   **목표:** 전처리된 Feature Vector를 입력받아, 기존의 `Gap Score` 계산 공식(논리/수학 모델)을 적용하여 최종진단점수를 산출합니다.
*   **핵심 기술 스택:** Python 백엔드 로직 (FastAPI), 비즈니스 규칙 엔진(BRE) 패턴 활용 권장.
*   **세부 작업 및 예상 소요 시간:**
    1.  **Diagnosis Controller 구현:** Phase I에서 얻은 Feature Vector를 입력받는 최종 API 엔드포인트(`POST /api/v1/diagnosis_score`) 정의. (0.5 Man-Day)
    2.  **Gap Score 계산 로직 통합 및 검증:** 기존에 설계된 Gap Score 공식(성장, 몰입도 등 가중치 포함)을 함수화하고, 오디오 지표와 연결하는 비즈니스 로직 구현. **[테스트 필수: 모든 경계 조건 테스트.]** (1.5 Man-Days)
    3.  **데이터 저장 및 트랜잭션 관리:** 진단 결과(Diagnosis\_Results) 및 KPI 기록(KPI\_Metrics)을 DB에 안정적으로 기록하는 트랜잭션 로직 구현. (1 Man-Day)
*   **총 예상 소요 시간: 3 ~ 3.5 Man-Days**

#### 3️⃣ Phase III: 권한 및 리포팅 연동 (기술 난이도: 하~중)
*   **목표:** 최종 진단 점수를 기반으로 사용자에게 맞춤형 피드백을 제공하고, 유료화 로직과 연결합니다.
*   **핵심 기술 스택:** Backend API 수정, Frontend Mockup -> 실제 컴포넌트 연동.
*   **세부 작업 및 예상 소요 시간:**
    1.  **RBAC(권한 기반 접근 제어) 검증 로직 적용:** 진단 점수와 함께 사용자의 구독 레벨을 비교하여, 유료 기능에 대한 접근 여부를 API 게이트웨이에서 차단하는 로직 구현. (1 Man-Day)
    2.  **JSON 응답 포맷 확정 및 프론트엔드 연동 준비:** 최종 사용자에게 전달될 JSON 구조를 명확히 하고, React/Next.js 컴포넌트에 바인딩할 인터페이스 정의. (0.5 Man-Day)
*   **총 예상 소요 시간: 1 ~ 1.5 Man-Days**
