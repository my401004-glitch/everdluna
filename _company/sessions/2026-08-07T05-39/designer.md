# 🎨 Designer — Designer는 데이터 입력 시 디자인 프로토콜이 자동으로 검증하는 통합 테스트 환경 구성을 위해, '데이터-구동형 디자인 시스템 구현 프로토콜(v1.0)'에서 정의한 QA 체크포인트와 자동화 규칙을 API/테스트 스크립트로 변환하기 위한 상세 설계안을 제시하라.

🎨 Designer: 작업 시작합니다.

CEO님의 지시와 코다리(Developer)의 통합 테스트 환경 설계안을 면밀히 검토했습니다. 현재 상황은 **"디자인 시스템의 규칙(Rule)이 데이터 구조를 넘어 실제 사용자 경험과 화면에 어떻게 반영되어야 하는가"**를 확정하는 단계입니다.

코다리가 제시한 `POST /api/v1/validate_diagnosis` 엔드포인트와 Schema-Driven Validation 방식은 기술적으로 완벽합니다. 제가 해야 할 작업은 이 **'기술적 검증 결과(Technical Error)'**를 가장 신뢰성 있고, 교육적이며, 브랜드의 전문성을 해치지 않는 **'사용자 경험 오류 메시지 및 UI 피드백 시스템'**으로 변환하는 것입니다.

따라서 이번에 가장 가치 있는 단일 작업은 단순히 체크포인트를 나열하는 것이 아니라, **QA 규칙을 디자인 시스템 컴포넌트로 재정의하고, 이를 반영한 상세 비주얼 스펙(Visual Spec)과 피드백 플로우차트**를 작성하여 코다리에게 전달하는 것입니다.

### 📄 산출물: [Design Spec] Validation Feedback System Guide (v1.0)
이 문서는 코다리가 설계한 `POST /api/v1/validate_diagnosis`의 응답 구조를 기반으로, 디자이너가 정의하는 시각적 규칙을 담고 있습니다.

#### 1. 핵심 원칙: '오류'는 곧 '학습 기회(Learning Opportunity)'이다.
*   **규칙:** 사용자에게 단순히 "잘못되었다"고 보여주는 것이 아니라, **"왜 잘못되었는지 (Cause)"**와 **"어떻게 개선해야 하는지 (Solution)"**를 명확히 제시합니다. [근거: Designer 검증된 지식]

#### 2. Validation Feedback 컴포넌트 정의
검증 실패 시 발생하는 모든 UI 요소에 통일성을 부여하기 위해 새로운 전용 컴포넌트를 정의합니다.

| 컴포넌트 이름 | 역할 및 기능 | 비주얼 스펙 (Design Token) | 적용 예시 |
| :--- | :--- | :--- | :--- |
| **Validation Alert** | 필드 단위의 실시간 오류 알림창. 가장 중요도가 높은 경고를 표시합니다. | 배경: Light Red/Pink 계열 (`#F8D7DA`), 테두리: `#DC3545`. 폰트: Montserrat Bold (강조). 아이콘: $\triangle$ (경고 삼각형). [근거: Designer 검증된 지식] | "⚠️ 안정도가 너무 낮습니다. 최소 0.7 이상으로 조정해주세요." |
| **Tooltip Guide** | 필드를 클릭하거나 포커싱 할 때 나타나는 상세 가이드라인/개선 방향 제시. | 배경: Light Yellow (`#FFF3CD`), 테두리: `#FFC107`. 아이콘: $i$ (정보). 폰트: Noto Sans KR (가독성 강조). [근거: Designer 검증된 지식] | "💡 Tip: 안정도는 피치 변화폭을 평균하여 계산합니다. 이 값을 높이려면... 등의 구체적 설명." |
| **Success State** | 데이터 유효성이 성공적으로 검증되었음을 사용자에게 알려주는 시각적 확신 제공. | 테두리/배경: Primary Color Dark Blue (`#0A2463`). 체크마크: $\checkmark$ (Green). [근거: Designer 검증된 지식] | "✅ 모든 데이터가 시스템 프로토콜을 통과했습니다." |

#### 3. API 응답 기반의 디자인 매핑 테이블
코다리가 제시한 `Error` 구조를 받아, 디자이너로서 어떤 시각적 처리를 할지 구체적으로 정의합니다.

| Technical Error Field (코드) | Trigger Message (예시) | Display Component | Visual Spec Guideline | 사용자 액션 유도 (UX) |
| :--- | :--- | :--- | :--- | :--- |
| `FIELD_MISSING` | 필수 입력 항목 누락. | Validation Alert + Tooltip Guide | Alert 배경: `#F8D7DA`. 메시지: "이 필드는 필수입니다." | 사용자에게 해당 필드를 *반드시* 채우도록 포커싱 이동 유도. |
| `MIN_VALUE` (예: pitch\_stability) | 최소값 미달. ("최소 안정도는 0.7 이상이어야 합니다.") | Validation Alert + Tooltip Guide | **Alert 색상:** 경고의 노랑/주황 계열 (`#FFC107`)을 사용하고, 그래프에 '위험 구간' 영역으로 명시함. | 개선 방향 제시: "그래프에서 파란색(목표)보다 낮은 부분을 확인하고 보정하세요." |
| `MAX_VALUE` (예: range\_variation) | 최대값 초과. ("최대 음역대가 너무 넓어 가창력이 분산됩니다.") | Validation Alert + Tooltip Guide | **Alert 색상:** 경고의 노랑/주황 계열. 시각화된 스펙트럼 그래프에 '위험 구간' 표시. | 제한 범위 설명: "가장 이상적인 범위는 X ~ Y 사이입니다." |
| `DATA_TYPE` (예: score) | 데이터 타입 오류. ("점수 값은 숫자로만 입력해야 합니다.") | Validation Alert + Tooltip Guide | **Alert 색상:** 일반적인 시스템 에러 Red (`#DC3545`). 메시지: "올바른 형식으로 수정해주세요." | 적절한 입력 형식을 예시로 보여주기 (Format Hint). |
