## ⚙️ I. 핵심 기술 로직 (Backend/API Spec Review)
### 1. 진단 점수 계산 로직 ($W_n$)
*   **엔드포인트:** `GET /api/v1/diagnosis_score`
*   **입력값:** `contextId`, `userId`
*   **출력 데이터 스키마 (Success Case):**
    ```json
    {
      "overallScore": 85, // 필수: 전체 진단 점수 (0-100)
      "kpis": {
        "Growth": 3.2, // 핵심 KPI 1: 성취도(0.0 - 5.0 범위 권장)
        "Engagement": 4.5, // 핵심 KPI 2: 몰입도(0.0 - 5.0 범위 권장)
        "Monetization": 2.8 // 핵심 KPI 3: 수익 잠재력(0.0 - 5.0 범위 권장)
      },
      "diagnosisType": "AI_VOCAL_GROWTH" // 필수: 진단 유형 식별자
    }
    ```

### 2. 주요 기술 병목 지점 (Technical Bottlenecks & Constraints)

| # | 병목 지점 (Bottleneck) | 원인 분석 (Root Cause Analysis) | 영향도 (Impact) |
| :--- | :--- | :--- | :--- |
| **B-01** | **API 응답 지연/Timeout** | 데이터베이스 복잡한 KPI 집계 쿼리 실행 시 네트워크 레이턴시 발생 가능. (특히 트래픽이 몰리는 상황) | **HIGH**. UI가 로딩 상태에 머무름. 사용자 경험 급격히 저하. |
| **B-02** | **데이터 유효성 오류** | API 요청 데이터(`contextId`, `userId`) 누락 또는 형식이 잘못된 경우 (e.g., ID가 숫자가 아님). | **MEDIUM**. 백엔드에서 4xx 에러 코드를 반환함. |
| **B-03** | **권한 부족 접근 시도** | 사용자의 계정 레벨이 특정 KPI 리포트(`Growth` 등)에 대한 조회 권한을 갖지 못한 경우 (RBAC). | **HIGH**. 민감 정보 노출 방지를 위해 로직 차단 필요. |

## 🛠️ II. Fallback Plan 및 디자인 지침 (Design/UX Handover)
기술적 오류(Bottleneck)는 단순 에러 메시지가 아닌, 사용자 흐름을 고려한 *의도된 상태*로 처리되어야 합니다.

### A. Fallback State 1: API 응답 지연/Timeout (B-01 대응)
**[기술 로직]** 클라이언트 측에서 **2초 초과 로딩 시**를 감지하고, 백엔드 호출을 중단한다.
**[디자인 구현 목표]** 사용자에게 '멈춤'이 아니라 '처리 중임'의 느낌을 주어야 한다.

*   **시각화 지침:**
    1.  로딩 스피너 대신, **"진단 점수를 계산하는 중입니다... (AI가 데이터를 조합하는 애니메이션)"** 형태의 미니 프로세싱 바를 보여준다. (점진적 로딩 느낌 부여)
    2.  애니메이션: `(0% -> 80%)`까지는 느리게, 마지막 `(80% -> 100%)`에서 점수가 확정되는 듯한 '스파크' 효과를 준다.
*   **필수 에셋:** 로딩 애니메이션용 배경 패턴 (추상적인 파동/데이터 흐름), 진행 바 트랜지션 에셋.

### B. Fallback State 2: 데이터 유효성 오류 (B-02 대응)
**[기술 로직]** 클라이언트에서 4xx 코드를 수신할 경우, **에러 코드와 함께 사용자에게 친절한 메시지를 표시한다.**
**[디자인 구현 목표]** 기술적 실패가 아닌, '사용자 입력 가이드'로 보이게 해야 한다.

*   **시각화 지침:**
    1.  **"점수 계산을 위해 필요한 정보(예: 진단 컨텍스트)를 다시 확인해주세요."** 와 같은 안내 메시지를 팝업/카드 형태로 보여준다.
    2.  에러 코드를 노출하지 않으며, 대신 **[재시도 버튼]**과 함께 *문제의 원인*을 간접적으로 설명하는 문구("최근 데이터를 불러오는 데 어려움이 있습니다.")를 포함한다.

### C. Fallback State 3: 권한 부족 접근 (B-03 대응)
**[기술 로직]** 백엔드에서 `403 Forbidden` 코드를 반환하며, **어떤 KPI가 제한되었는지(예: Growth)**에 대한 정보를 담아 온다.
**[디자인 구현 목표]** 사용자가 '유료 전환'이 필요하다는 사실을 인지시키되, 강압적이지 않아야 한다.

*   **시각화 지침:**
    1.  해당 KPI 섹션 전체를 비활성화된 것처럼 (Dimmed) 처리한다.
    2.  대체 텍스트: **"이 리포트는 프리미엄 진단 기능에 포함되어 있습니다. 더 깊이 있는 분석을 원하시면 구독 페이지에서 확인하세요."** 라는 자연스러운 CTA와 함께 표시한다.

---
*   **[Codari의 자가 검증 코멘트]**: 이 문서는 기술적 제약을 시각적으로 풀어낸 중요한 다리 역할을 합니다. 특히 B-03은 비즈니스 모델(Monetization)과 직결되므로, 디자인팀이 이를 가장 '예쁘게' 처리하는 것이 중요합니다.
