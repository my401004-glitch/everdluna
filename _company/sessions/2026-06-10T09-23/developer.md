## 🟢 섹션 1: 데이터 & 백엔드 로직 검증 (Data Pipeline & Backend Logic Validation)

### 1.1 진단 데이터 수집 및 무결성 체크
*   **[필수] RBAC 접근 권한 검증:** 요청된 `diagnosis_type`에 대해 사용자가 현재 가지고 있는 Role(역할)로 접근이 허용되는지 DB 레벨에서 확인한다. (실패 시: 403 Forbidden 응답 반환 및 로그 기록).
*   **[필수] 입력 스키마 유효성 검증:** 외부 API 또는 사용자 입력을 통해 들어오는 모든 데이터(`result_data`)가 정의된 JSON 스키마를 따르는지 확인한다. 특히 `KPI` 필드(Growth, Engagement, Monetization)는 필수 포함 및 범위 제한을 적용해야 한다.
*   **[필수] 트랜잭션 격리 검증:** 진단 결과 기록(`Diagnosis_Results`)과 KPI 수치 저장(`KPI_Metrics`)이 하나의 원자적 단위(Atomic Unit)로 처리되는지, 그리고 실패 시 롤백 로직이 작동하는지 확인한다.

### 1.2 API 안정성 및 에러 핸들링
*   **[필수] Rate Limiting 검증:** 진단 요청 API가 트래픽 초과에 대비하여 적절한 `Retry-After` 헤더와 함께 응답하는지 테스트해야 한다. (최대 3회 재시도, 지수 백오프 적용).
*   **[검증] 데이터 파이프라인 누락 값 처리:** 핵심 KPI 중 하나라도 누락되거나 비정상적인 값이 들어올 경우(예: `null` 또는 음수), 시스템은 기본값(`default_value`)을 사용하거나 해당 필드를 제외하고 경고 로그만 남긴 후 성공적으로 응답해야 한다.

## 🟡 섹션 2: 미디어 합성 파이프라인 검증 (Media Synthesis Pipeline Validation)

### 2.1 오디오-비주얼 동기화 및 안정성
*   **[필수] 시간 축 정합성(Time Axis Alignment):** 비주얼 전환점(Color change, Graphic appearance)과 오디오의 주요 이벤트 포인트(BPM 변화, 사운드 피크)가 50ms 이내로 일치하는지 검증한다. (Drift Tolerance: $\pm 50\text{ms}$).
*   **[필수] 음악 합성 Fallback 로직:** 외부 AI 음악 API 호출이 실패할 경우(Timeout/Error), 미리 준비된 `Fallback Audio Kit`을 사용하여 사전에 정의된 BPM과 키에 맞는 대체 트랙으로 자동 전환되어야 한다.
*   **[검증] 오디오 파일 무결성:** 최종 합성된 모든 오디오 파일(`*.wav`, `*.mp3`)이 비트 전송률(Bitrate) 및 샘플링 레이트(Sample Rate) 규격에 맞는지 확인한다.

### 2.2 시각적 일관성 검증
*   **[필수] 테마 일관성:** 모든 콘텐츠 섹션에서 정의된 메인 컬러 팔레트 (Dark Blue/Accent Yellow 등)가 벗어나지 않도록 CSS 변수를 통해 강제 적용되었는지 확인한다.
*   **[검증] 해상도 및 비율 검사:** 최종 썸네일, 쇼츠 영상 등이 목표 사양(예: 16:9 또는 9:16)을 정확히 준수하는지 크기/비율 체크를 수행한다.

## 🔴 섹션 3: 통합 배포 환경 테스트 (Integration & Deployment Test)
*   **[필수] 캐싱 무효화 검증:** 콘텐츠 변경이 발생했을 때, CDN 및 백엔드 캐시가 즉각적으로 무효화되고 최신 버전의 리소스만 사용자에게 제공되는지 확인한다.
*   **[검증] 로딩 성능 측정:** 모든 에셋(이미지, 비디오)을 포함하여 최종 페이지/영상 클라이언트의 초기 로딩 속도(TTI: Time to Interactive)가 2초를 초과하지 않는지 검증한다.
