## 진단 과정 애니메이션 및 인터랙티브 플로우 최종 가이드라인 설계

CEO의 지시사항("진단 과정의 애니메이션 흐름과 인터랙티브 플로우를 PoC 시나리오 기반으로 설계하라")에 따라, 'Pain $\rightarrow$ Gain' 프레임워크를 극대화하여 사용자의 감정적 몰입과 데이터 신뢰도를 동시에 확보하는 디자인 가이드라인을 확정합니다.

이 가이드라인은 **DiagnosisFlowSimulator** 컴포넌트의 시각적 구현과 사용자 인터랙션 설계의 근간이 됩니다.

### 1. 핵심 비주얼 시스템 (Visual System Recap)

기존에 확정된 브랜드 비주얼을 진단 과정 전체에 일관되게 적용합니다.

| 요소 | 설정 값 | 적용 목적 |
| :--- | :--- | :--- |
| **Primary Color (신뢰/안정)** | Dark Blue (`#0A2463`) | 배경, 핵심 정보 영역, 신뢰감 확보. |
| **Accent Color (행동 유도/기회)** | Accent Yellow (`#FFD700`) | Pain(위험) 표시, Gain(이득), 최종 CTA 강조. 즉각적인 시선 집중 유도. |
| **Background Color (가독성)** | Neutral Grey (`#F5F5F5`) | 본문 텍스트 배경으로 사용, Dark Blue와의 명확한 대비를 통해 데이터 영역을 구분. |
| **Title Typography** | Montserrat Bold | 핵심 메시지(Pain, Gain) 강조. 강력한 시각적 임팩트 제공. |
| **Body Typography** | Noto Sans KR | 구체적인 데이터 및 상세 설명 텍스트에 사용, 높은 가독성 보장. |

### 2. 애니메이션 흐름 (Animation Flow: Pain $\rightarrow$ Proof $\rightarrow$ Solution)

진단 과정은 세 단계로 명확하게 분리되어 사용자에게 '문제 인식'에서 '해결책 수용'까지의 감정적 여정을 시각화해야 합니다.

#### **A. 단계별 목표**

1.  **Pain (고통/위험 인지):** 사용자의 현재 상태가 위험하고 개선이 필요함을 직관적으로 인지시킨다. (감정 유발)
2.  **Proof (증명/분석):** AI 진단 결과와 데이터 기반의 객관적인 분석을 제시하여 신뢰를 구축한다. (논리적 확신 제공)
3.  **Solution (해결책/기회):** 구체적인 맞춤형 솔루션(모듈, 경로)을 제시하고 다음 행동을 유도한다. (행동 촉구)

#### **B. 시각적 흐름 상세 설계 (Visual Flow Detail)**

| 단계 | 애니메이션 컨셉 | 주요 시각 요소 | 색상 적용 | 인터랙션 연동 |
| :--- | :--- | :--- | :--- | :--- |
| **1. Pain** | **위험 경고 및 집중** | 화면 중앙에 Pain Point를 강조하는 큰 타이포그래피 (`Montserrat Bold`)와 함께, 이탈 위험 지표(Risk Score)를 시각적으로 표시. | 텍스트: `#FFD700` (경고), 배경: `#0A2463` (안정감). | 사용자가 다음 단계로 넘어가기 위해 **'다음 분석 보기'** 버튼을 클릭할 때만 전환. |
| **2. Proof** | **데이터 심층 탐색** | 데이터 그래프(Bar/Line)가 동적으로 채워지며, Pain과 Gain 사이의 간극($\text{Gap}$)을 시각화하는 모션 그래픽(`Pain $\rightarrow$ Gain` 흐름). | 데이터 바: `#0A2463`, Gap 영역: `Accent Yellow (#FFD700)`. | 각 지표(Growth, Engagement 등)를 클릭하면 해당 데이터의 상세 분석 팝업이 나타나며, **신뢰도**가 상승하는 애니메이션 적용. |
| **3. Solution** | **맞춤 경로 제시** | 진단 결과에 따라 가장 적합한 솔루션 모듈(예: Gap Module Recommendation)을 명확하게 박스로 분리하여 제시. | 솔루션 박스 배경: `Neutral Grey (#F5F5F5)`, CTA 버튼: `#FFD700`으로 강조. | 사용자가 특정 모듈을 선택할 때, 해당 모듈에 대한 **'ROI 예측 시나리오'**가 동적으로 계산되어 표시되도록 설계. |

### 3. 인터랙티브 플로우 가이드라인 (Interactive Flow Guidelines)

사용자가 단순히 정보를 소비하는 것을 넘어, 능동적으로 솔루션을 탐색하도록 유도합니다.

1.  **다이내믹 스코어링 (Dynamic Scoring):**
    *   각 진단 단계(Pain $\rightarrow$ Proof $\rightarrow$ Solution)를 완료할 때마다 사용자에게 **'현재 상태 점수'**가 변화하는 것을 보여줍니다. 이 점수는 단순한 숫자가 아닌, '잠재적 수익($\text{ROI}$)'으로 해석되어야 합니다.
    *   예: Pain 단계에서 시작하여 Proof 단계를 거치면, "당신의 잠재적 ROI는 30% 상승 가능합니다!"와 같은 메시지를 `Accent Yellow`로 강조하여 제시합니다.

2.  **시나리오 기반 분기 (Scenario-Based Branching):**
    *   사용자가 초기 진단 시 **[Predictive Lead Scoring]**, **[Gap Module Recommendation]**, 또는 **[Time Efficiency]** 중 하나를 선택하면, 시스템은 즉시 해당 시나리오에 최적화된 애니메이션과 데이터 레이아웃으로 전환합니다.
    *   이때, 선택한 시나리오의 목표(Core ROI Metric)가 화면 상단에 고정되어 사용자가 현재 무엇을 달성하려 하는지 명확히 인지하게 합니다.

3.  **결과 기반 CTA (Result-Driven CTA):**
    *   모든 분석이 완료된 후, 최종 결과 페이지는 단순한 요약이 아니라, **"다음 행동(Next Action)"**에 대한 구체적인 제안으로 끝나야 합니다.
    *   CTA 버튼은 추상적이지 않고, 앞서 정의된 ROI 목표와 직접 연결되어야 합니다. (예: "최적의 경로를 위한 4주 플랜 시작하기 [Gain Path]", "지금 바로 맞춤 모듈 구매하기 [ARPS 증명]")
