### 🔍 1. 데이터 수집 실패 원인 분석 및 누락 항목 진단

최근 `my_videos_check` 및 `comment_harvester` 시도가 어려움을 겪은 것은, 단순히 코드가 잘못되었기보다 **데이터의 '접근 권한'과 '구조적 의존성'**에 문제가 있을 가능성이 높습니다.

#### ⚠️ 주요 실패 원인 (Potential Root Causes)
*   **[권한/인증 문제] API Scope 누락:** 가장 빈번하게 발생하는 문제입니다. 필요한 데이터(예: 특정 채널의 상세 조회, 사용자 댓글 전체 목록 등)를 가져오려면 단순히 기본 인증 외에 `READ_CHANNEL_METRICS`와 같은 **추가적인 OAuth 스코프**가 필요할 수 있습니다.
*   **[데이터 의존성 문제] 참조 목록 부재:** 코드가 작동하려면 필요한 '앵커(Anchor)' 데이터 리스트가 누락된 것으로 보입니다. 예시로 언급하신 `WATCHED_CHANNELS` 목록처럼, 데이터를 조회하는 데 필요한 **최소한의 기준점 (Minimum Viable Data Set)**이 필요합니다.
*   **[구조적 문제] API 응답 Schema 변경:** 외부 API(예: YouTube Data API)는 예고 없이 응답 필드를 변경할 수 있습니다. 코드가 기대하던 JSON 구조와 실제 받은 데이터가 달라 오류를 일으킬 수 있습니다.

#### 📊 핵심 누락 항목 (Critical Missing Items)
1.  **✅ 공식 API 접근 승인 범위:** 현재 모든 기능 구현에 필요한 최종적이고 광범위한 OAuth 스코프 목록 및 재확인이 필요합니다.
2.  **✅ 기준 데이터셋(Seed Data):** 테스트를 진행할 실제 사용자의 ID 리스트, 또는 특정 채널의 최소 10개 이상의 조회 이력(`WATCHED_CHANNELS`) 같은 **구체적인 샘플 데이터가 필수적**입니다.
3.  **✅ 에러 처리 로직 강화:** 실패 원인을 명확히 파악하기 위해 단순한 `try-catch`를 넘어, API 응답 코드별/예외 메시지별로 세분화된 오류 로깅 시스템을 구축해야 합니다.

1.  **[필수 조치] 데이터/API 요구사항 최종 체크리스트 작성:** 필요한 모든 API 스코프, 필수 데이터 항목, 예상되는 예외 상황을 한곳에 모아 Codari와 CEO가 검토해야 합니다.
