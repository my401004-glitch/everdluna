### 2. 기술적 제약사항 보고 (Implementation Constraints)

디자인 요구사항을 실제 데이터로 구현할 때 발생할 수 있는 주요 기술적 제약사항은 다음과 같습니다.

1.  **데이터 집계의 복잡성 (Aggregation Complexity):**
    *   `The Journey Map` 시각화는 단순한 과거 기록 나열이 아니라, **'좌절(낮은 점수) → 노력(과정 변화) → 성취(높은 점수)'**라는 서사적 흐름을 반영해야 합니다. 이는 단순 합산이 아닌, **상대적 변화율(Rate of Change)**과 **감성적 변곡점(Turning Point)**을 계산하는 복잡한 백엔드 로직(SQL 또는 Python 비즈니스 로직)이 필요합니다.
2.  **AI 서사 생성의 일관성 (Narrative Consistency):**
    *   Intro 섹션에서 요구되는 '3줄 솔루션'은 단순히 데이터 요약이 아니라, 과거 기록을 바탕으로 **동기 부여하는 스토리텔링**이어야 합니다. 이는 API 응답 시 LLM(예: GPT 또는 자체 모델)을 호출하여 데이터를 입력으로 받아 텍스트를 생성하는 추가적인 AI 파이프라인 레이어가 필요합니다.
3.  **데이터 정규화 및 프론트엔드 매핑 (Normalization & Mapping):**
    *   비주얼 시스템에서 요구하는 색상(네이비/골드/오렌지)과 데이터 값(Gap Score) 간의 **매핑 로직**을 명확히 정의해야 합니다. 데이터가 들어왔을 때, 프론트엔드가 해석하기 쉬운 표준화된 스케일로 변환하는 과정이 필요합니다.
4.  **성능 제약 (Performance Constraint):**
    *   사용자가 리포트를 요청할 때, 모든 과거 수업 기록과 로그를 실시간으로 계산하여 JSON으로 반환하면 데이터 볼륨에 따라 API 응답 시간이 지연될 수 있습니다. 따라서 **미리 계산된 요약 데이터(Pre-calculated Summary Data)**를 캐시하거나, 리포트 생성 시점에만 필요한 최소한의 데이터를 요청하는 효율적인 API 설계가 필수적입니다.
