### 🛠️ 에이전트별 작업 분배 계획 (Next Action Items)

이번 작업은 **비즈니스 가설을 가장 잘 알고 있는 현빈님**과, 이 가설을 **가장 현실적으로 구현할 수 있는 코다리님**의 협업이 필수적입니다.

#### 1️⃣ [현빈] 역할: Pain Point 심화 및 핵심 지표 정의 (Business Focus)
*   **목표:** 학원 운영자가 가장 '손해'를 본다고 느끼는 **구체적인 시나리오 기반의 비즈니스 리스크(Pain Point)**를 3가지로 압축합니다.
    *   *(예시 Pain Point: "학생들이 시험 기간에 어떤 부분을 취약한지, 강사에게 데이터를 요청하는 과정 자체가 너무 오래 걸려서 수업 준비 시간이 부족하다.")*
*   **산출물:** 이 리스크를 해결했을 때 운영자 입장에서 **'측정 가능하고 명확하게 돈으로 환산할 수 있는 단일 지표 (KPI)'**와 그에 대한 근거 설명을 정리합니다.

#### 2️⃣ [코다리] 역할: 기술적 실현 가능성 검토 및 API 로직 설계 (Technical Focus)
*   **목표:** 현빈님이 정의한 **'가장 강력한 Pain Point' 하나**를 선택하고, 이 문제를 해결하기 위해 필요한 최소한의 데이터 입력/처리/출력 흐름을 설계합니다.
    *   *(예시: 리스크 '데이터 요청 시간 지연' $\rightarrow$ 필요한 API는 `request_status(user_id)`와 `report_generation_time` 측정 로직 등)*
*   **산출물:** B2B PoC에 사용할 **가상의 데이터 입력/처리 플로우차트 및 핵심 기능의 API 호출 순서 (Mock API 시퀀스)**를 작성합니다.

#### 💡 기대되는 최종 산출물: 통합 'Pain Point 기반 데모 스크립트 초안'
