| **Developer** | 3. 데이터 시뮬레이션 환경 구축 | **[근거: DiagnosisService]**: 영상 편집 과정에서 사용할 가상 데이터를 정의하고, API 호출이 원활하도록 '시뮬레이터'를 준비한다. 실제 라이브 API 연동은 최종 단계에 맡긴다. (예: `dummy_diagnosis_api` 구현) | 시뮬레이션용 데이터셋 및 개발자 참고 자료 |
| **레오** | 4. 로직 통합 점검 | **[종합]**: Writer와 Designer가 준비한 스크립트의 특정 지점(Pain Point 발생 지점)에서, Developer가 만든 KPI 데이터를 정확히 시각화할 수 있는지 최종 검토한다. | 프로덕션 체크리스트 V1.0 |

## 📹 Phase 2: 프로덕션 (Production) - 기간 산정 목표: D+5일
*(모든 녹화 및 영상 소스를 확보하는 단계입니다.)*

| 담당 | 주요 작업 항목 | 세부 실행 지침 및 근거 | 필수 자원/소스 |
| :--- | :--- | :--- | :--- |
| **Writer** | 1. 나레이션 녹음 (Voice Over) | 전문 컨설턴트의 냉철하고 권위 있는 톤을 유지한다. 감정적 기복은 절대 금물이다. 속도감과 리듬에 맞춰 스크립트를 암송한다. | 고품질 VO 파일 (.wav 또는 .mp3) |
| **Director/Talent** | 2. 인터뷰 및 설명 녹화 | 핵심 메시지 전달자(대표 등)는 카메라를 보고 전문성을 어필해야 한다. 배경은 '데이터가 가득한 오피스' 컨셉이 좋다. (신뢰도 확보 목적) | 고해상도 영상 소스 (Talking Head) |
| **Designer/Editor** | 3. 목업 기반 스크린캐스트 녹화 | **[근거: Mockup Spec V2.0]**: 실제 서비스 화면을 보여주되, 반드시 '진단 리포트'의 핵심 컴포넌트를 중심으로 클로즈업하여 촬영한다. (데이터 시각화에 집중) | 고해상도 스크린캐스트 영상 소스 |
| **Developer** | 4. 데이터 인터페이스 제공 | 녹화 과정 중 실시간으로 데이터를 보여줘야 할 때, 준비된 API 시뮬레이션 환경을 통해 즉시 값을 확인할 수 있도록 개발팀이 대기한다. | 기술적 안정성 확보 (백업 플랜) |

| 담당 | 주요 작업 항목 | 세부 실행 지침 및 근거 | 최종 검토 포인트 |
| :--- | :--- | :--- | :--- |
| **Editor** | 1. 영상 구조 편집 및 연결 | 스크립트의 흐름(Pain $\rightarrow$ Diagnostic $\rightarrow$ Solution)에 맞춰 소스를 붙인다. 초반 30초 이탈 지점 방지를 위해, 충격적인 데이터 비주얼을 배치한다. (강력한 후킹 설계) | 시청 지속률 그래프 분석 필요 |
| **Designer** | 2. 모션 그래픽/자막 제작 | 모든 통계 수치와 키워드는 애니메이션 효과를 적용하여 강조해야 한다. 특히, '위험 지표(빨간색)'와 '개선된 점수(파란색)'의 대비를 극대화한다. | 데이터 시각화의 명확성 및 임팩트 |
