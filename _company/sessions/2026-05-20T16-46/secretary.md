### 1. Core Business Logic Implementation (가장 중요)
*   **Task:** `calculate_proi` 함수 구현. 이 함수는 독립적으로 존재해야 하며, 입력 변수(`input_gsm`, `input_evs`)와 버전 관리된 가중치(Weights)를 기반으로 $pROI$ 값을 계산하는 핵심 비즈니스 로직을 담당합니다.
*   **기술 요구사항:** 해당 함수의 모든 연산 과정과 사용되는 상수/가중치를 주석 및 테스트 케이스로 명확히 기록하여 재현 가능성을 극대화해야 합니다.

### 2. Database Schema & Integration (데이터 연결)
*   **Task:** `Analysis_Metrics` 테이블을 실제 DB 스키마에 반영하고, 이 테이블과 `Diagnosis_Results` 간의 외래 키(FK) 관계를 확립합니다.
*   **기술 요구사항:** 새로운 $pROI$ 계산 결과를 기록하는 트랜잭션 로직을 구현하여 데이터 누락 없이 안정적으로 저장되게 합니다.

### 3. API Endpoints & Testing (최종 검증)
*   **Task A: 통합 엔드포인트 구축:** 기존의 진단 결과 조회 API(`diagnosis_score` 또는 유사한 메인 진단 로직)를 수정하여, **진단 실행 완료 시점에서 $pROI$ 계산 및 저장 과정을 필수로 거치도록** 만듭니다.
*   **Task B: E2E 테스트 케이스 작성:** 핵심 비즈니스 로직이 API 호출을 통해 정상적으로 작동하는지를 검증하는 End-to-End(E2E) 통합 테스트 스크립트(Test Case)를 최우선으로 작성합니다. (예: GSM/EVS 값이 특정 범위일 때 $pROI$가 예상대로 계산되는지 검증).
