*   **문제점:** 현재 영상 제작 파이프라인은 로컬 스코프 변수(`UnboundLocalError`)와 비동기 데이터 흐름 관리 미흡으로 인해, 특정 조건(예: 사용자의 진단 유형에 따른 권한 검증)에서 예측 불가능하게 실패합니다. 또한, KPI 데이터가 독립적으로 저장되어 트랜잭션 일관성이 깨지기 쉽습니다. [근거: sessions/2026-07-28T04:32]
*   **목표:** 핵심 비즈니스 로직(진단 점수 계산 및 권한 체크)을 **트랜잭션 경계 내에서 원자적으로 처리**하고, 모든 외부 입력에 대해 엄격한 데이터 유효성 검사(Schema Validation)를 적용하여 안정성을 확보한다.

#### 3. API 로직 수정 명세 (Technical Specification - P0 Focus)
가장 문제가 된 엔드포인트는 `/api/v1/diagnosis_score` 입니다. 이 엔드포인트의 핵심 개선사항은 다음과 같습니다.

**Endpoint:** `GET /api/v1/diagnosis_score`
**기존 문제점:** 비동기 로직 내에서 지역 변수 참조 오류 (`UnboundLocalError`) 발생 가능성 높음. 권한 체크가 실패해도 예외 처리가 미흡하여 전체 파이프라인이 멈춤. [근거: sessions/2026-07-28T04:32]
**개선 방안 (P1 - Must Fix):**

1.  **트랜잭션 및 스코프 관리:** 모든 진단 점수 계산 로직은 단일 트랜잭션 함수 내에서 실행되어야 합니다. 지역 변수는 외부 호출을 받기 전에 반드시 명시적으로 초기화하거나, 클래스 멤버 변수로 승격시켜 스코프 문제를 근본적으로 해결해야 합니다.
2.  **권한 검증 강화 (RBAC):** 요청이 들어올 때마다 사용자 토큰에서 `role`과 `subscription_level`을 추출하고, 진단 유형(`diagnosis_type`)에 대해 접근 권한 체크를 **가장 먼저 수행**합니다. 이 단계에서 실패하면 즉시 403 Forbidden 에러를 반환해야 합니다. [근거: sessions/2026-05-18T13-43/developer.md]
3.  **데이터 유효성 검증:** 진단 결과가 계산된 후, 전송되는 JSON 응답 구조는 `DiagnosisScoreSchema`를 따르는지 서버 레벨에서 이중으로 확인합니다. (스키마 기반 유효성 검사 라이브러리 사용 권장).

#### 4. 기술적 실행 단계 (Implementation Roadmap)
1.  **Phase 1: DB/Schema Refactoring:** `schema.sql` 수정 및 마이그레이션 스크립트 작성. (우선순위 P0)
2.  **Phase 2: Core Logic Isolation & Unit Test:** `/api/v1/diagnosis_score` 로직을 순수 함수(Pure Function)로 분리하고, Mock 데이터를 사용한 단위 테스트 케이스를 최우선으로 작성합니다. (UnboundLocalError 해결의 핵심).
3.  **Phase 3: Integration & Testing:** 개선된 API와 DB 스키마를 통합하고, `qa_automation_runner`에 새로운 실패 시나리오(예: 권한 미비 테스트)를 추가하여 회귀 테스트를 수행합니다.
